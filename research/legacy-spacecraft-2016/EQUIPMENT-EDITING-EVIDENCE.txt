2016 spacecraft equipment editing
=================================

Recovered through read-only Ghidra MCP calls with explicit program names.
No original DLL was executed and no native harness was built or run.

The public offline editing API is PlaceDetail/DeleteDetails in
src/lib/data/designs/aulegacyshipdetails.h. Each placement invokes the existing
DnDetail::IsValid port, using the complete original 143-entry GD placement
table, room fallback flags, station limits, spacing, stair footprints and
original vehicle bounds. DetailName copies the GD names verbatim; placement
descriptions are explanations of the recovered rules, not new restrictions.

AuData13.dll SpaceShipDesignAddDetail 0x180142960 first validates and snaps XY
using EncodeGridCoord 0x18017a390: round(component/2.8284271245), signed byte
coordinates restricted to -120..120. RoundGridCoordOnDeck 0x18015b600 confirms
the half-cell snap and round-away-from-zero behavior. Detail validation allows
decks -42..42; the spacecraft designer UI itself has the narrower -28..28 range.

Ordinary placement ignores pivot 76, contrail emitter 98 and weapon emitter 99
when looking for equipment to replace at a point. The first ordinary matching
location is removed when its exact type differs. Matching exact types return
unchanged, even if a different commodity was requested. There is no rotation
inside this data-level function. Rotation is encoded in distinct detail types;
the public helpers preserve the exact DnDetailType::Rotation mappings.

Stair placement removes ordinary equipment whose origin lies in its footprint;
CanBeOnStairEdge 0x18002c720 exempts eligible details on the edge. Existing
stairs are replaced when one of their footprint vertices is strictly inside
the new footprint. Non-stair placement rejects points inside existing stairs,
and rejects their edges unless the new type can lie on a stair edge. This is
followed by the existing exact IsValid placement and spacing checks.

The original performs replacement deletions before validating the candidate.
The offline editor deliberately stages deletions and commits only when the
candidate succeeds. Rejected placement therefore leaves the design unchanged.
Unavailable dependencies also roll back the whole brush event. Ordinary
invalid peripheral brush positions are skipped without removing equipment.

SpaceShipDesignNextDetailId 0x1801485e0 chooses the lowest unused positive
32-bit ID after replacement deletions. DnDetailArray::Add 0x18015c210 inserts
in ascending signed deck, room ID, detail ID order; existing records are not
globally resorted. A new detail gets the current design ID and zero hidden byte.

SpaceShipDesignFillDetails 0x1801469d0 places the center first, then expands
only if the center returns a nonzero room ID. The square brush visits X then
Y in ascending order, offsetting by float(index)*float(2.8284271245), then
rounding back to the grid. Only points in the center's returned room are used.
The room boundary is additionally allowed for types 10, 14, 16, 18 and 23,
as encoded by the original bitmask 0x854400. Brush radius is 0..25 in the
original AuView increment/decrement handlers (EXE 0x1402e8cb0/0x1402e8c90).

SpaceShipDesignDeleteDetail 0x1801454d0 removes the first record at the snapped
location. A type filter compares that first record; it does not keep searching
through coincident records for another type. AuAtom13.dll DesignDetail
0x1803e3e70 expands erasure only after removing the center, and peripheral
points remove only the center's exact removed type. The brush does nothing
when its center is empty. Hidden records are not filtered from these operations.
A retained type-zero source record is removed at the center, but its original
zero return value prevents the erase brush from expanding to nearby records.

Special placement routes in that same DesignDetail function:
  76 pivot: validate, remove all existing pivots, allocate ID and insert.
  98 contrail emitter: validate and enforce at most ten on the whole ship.
  99 weapon emitter: validate the existing one-per-Room-Number restriction.
These routes do not apply the brush radius. Their data functions are captured
as SpaceShipDesignAddPivotPoint, AddContrailEmitter and AddWeaponEmitter.

Flag pole 100 and light pole 142 have outdoor-building placement -8 and cannot
be placed on spacecraft: IsValid's spacecraft flag rejects placement outside
all rooms, while placement -8 rejects every intersected room. Troop stations
may be outside a building but must be inside a spacecraft room. No invented
spacecraft permission is supplied for these building-specific rules.

Manual native coverage is in tests/native_detail_edit.cpp. It exercises atomic
replacement, IDs and insertion order, duplicate stations, snapping, brush
center/type/room constraints, bridge fallback, vehicle footprint and dependency
failure, special marker limits, doors/hatches and rotation mappings.
