2016 spacecraft room painting: recovered behavior
Captured 2026-10-04. No build or original-client edit was run for this recovery.

Scope and evidence
------------------
This is an implementation specification from read-only static analysis of the
2016 AuAtom13.dll and AuData13.dll. Function names below come from PE exports.
Raw decompilations and assembly cross-checks are in pseudocode/.
Decompiled locals/types are not original
source. Conclusions marked INFERENCE still need controlled old-client edits.

Cell shapes and UI gestures are recovered separately (see CONTROL-MAPPING.txt
for the actual left-button commands). This document starts at
DaDesignEnvironment::FillRoomCell and follows the spacecraft editing path.
The native port is aulegacyshipgeometry.cpp / aulegacyshipedit.cpp; equipment
rules are in EQUIPMENT-RECONCILIATION.txt. Current UI scope is in README.txt.

Important consequence: rooms are not arbitrary independently paintable polygons.
The ordinary add path identifies a room by (deck, type, subtype), and its
geometry machinery uses a raster plus a single boundary trace. In particular,
do not replace it with an unrestricted polygon union/difference or assume that
erasing a bridge between regions creates two room records.

1. Dispatch and coordinate rules
-------------------------------
AuAtom13.dll 0x1802f8ed0, DaDesignEnvironment::FillRoomCell:

  Find the design plane for the supplied avatar/id. Missing plane => return.
  For a nonnegative requested room type and nonzero plane RoomMode:
    RoomMode 1 => change the type of the room under the cursor.
    Any other nonzero mode => return.
  Otherwise ask GetFillShapeAt(cursor) for a cell polygon.
  Empty result => return.
  For nonnegative types in spacecraft mode, cursor deck must be within
    DeckMinLimit() = -28 and DeckMaxLimit() = 28, inclusive.
  Pass polygon, requested type, and plane byte +0x3ba to DesignRoom.
    That final byte becomes DnRoom +0x08: the saved room subtype (rsub).
  A successful return marks an unmodified environment modified and notifies it.

The byte +0x3ba is the user-facing Room Number, separately recovered in
CONTROL-MAPPING.txt; the parameter flow into DnRoom::rsub is direct. Increment
and decrement wrap its byte modulo 256. See FORMAT.txt for the SQL
binding evidence identifying +0x07 as rtype and +0x08 as rsub.

AuAtom13.dll 0x1803e55c0, DaSpaceShip::DesignRoom:

  Reject if CanDesignBeModified() is false.
  requested type >= 0 => SpaceShipDesignAddRoom(..., byte(type), subtype).
  requested type == -2 => SpaceShipDesignDeleteRoomCompletely(...).
  any other negative value => SpaceShipDesignDeleteRoomCells(...).
  On success clear the cached path and invalidate path data.

The normal UI uses -1 for cell erasing; the lower-level dispatch accepts other
negative values the same way except -2. Erasing bypasses the environment's
[-28,28] add-deck check. Room-mode type changing also bypasses that add check.

For all three polygon operations, DgData first checks read-only state, requires
at least three vertices, and validates every XY vertex. Deck is calculated
from the first vertex as round(z / 8), not from the mouse directly. These
functions do not separately check coplanarity or validate z for every vertex;
the normal cell generator supplies a common deck.

AuData13.dll 0x18017acb0, DnSpaceShip::IsValidGridCoord:
  -120 <= round(x / 2.8284271245) <= 120
  -120 <= round(y / 2.8284271245) <= 120
This checks the rounded half-grid coordinates, not exact grid alignment.
The generated grid endpoints are therefore at most 60 full cells from origin.
Use C/C++ round semantics (half away from zero), not Python's default round.

The environment instead uses DnSpaceShip::OnDeck(cursor.z), already recovered
at 0x18015b510: floor((z + 0.05) / 8), clamped to [-127,127]. These formulas
normally agree on generated deck planes but are not interchangeable for
arbitrary cursor points.

2. Add or repaint cells
----------------------
AuData13.dll 0x180143450, DgData::SpaceShipDesignAddRoom polygon overload:

  A. Find the FIRST room matching design, deck, requested type, requested subtype
     and copy its boundary. Lookup is SpaceShipDesignRoomBoundary, 0x180148f40.
  B. If its boundary has fewer than 3 points, use the new polygon as the proposed
     boundary and take the new-room path.
  C. Otherwise call DnRoom::IntersectRoomBoundary(existing, newPolygon).
     Despite its name this combines occupied raster areas and traces their
     boundary; it is the add/merge operation, not geometric intersection.
     Failure or unchanged result => reject the entire operation.
  D. Preflight every existing room on that deck with a DIFFERENT (type,subtype),
     except existing types 0x16, 0x17 and 0x18 (roof types).
     CanSubtractRoomBoundary(other, proposedCombinedBoundary) must succeed for
     every such room. A failure returns before any room boundary is changed.
  E. For the same set, subtract the proposed combined boundary. If subtraction
     changes a room to >=3 points, replace its boundary and send an update.
     If it changes the boundary to <3 points, delete that room record.
     If subtraction reports unchanged, leave that room untouched.
  F. Existing-key path: replace the FIRST matching room boundary in place
     using SpaceShipDesignSetRoomBoundary (0x180149a50), preserving its room ID.
     New-key path: create a room with a freshly selected room ID, given deck,
     type and subtype, append it and notify its addition.
  G. VerifyDetails(design), then return true.

The preflight/subtraction uses the entire combined target boundary, not just
the newly painted cell. Existing roof records are excluded from overlap
subtraction; the code does not similarly exempt a requested roof type from
subtracting other ordinary records. Roof creation UI is a separate concern.

Identity consequences:
  - Same type but different subtype is a different room key and competes for
    occupied cells through subtraction.
  - Same type/subtype on a different deck is a different room.
  - Painting a disconnected island with an existing key is not implemented as
    allocating a second same-key room: it must pass the raster add operation.
  - Unexpected duplicate same-key records loaded from a file are not normalized
    by this function: boundary lookup/replacement uses the first match and the
    subtraction loops skip all same-key records.
  - A paint fully contained in the existing raster is rejected as no change.

AuData13.dll 0x180148760, SpaceShipDesignNextRoomId:
  Choose the smallest unused nonzero unsigned 16-bit room ID across the whole
  design, starting at 1. IDs can be reused after deletion. Exhausting all
  nonzero IDs wraps to 0; the callers shown do not add an exhaustion check.

3. Erase cells versus erase entire rooms
---------------------------------------
AuData13.dll 0x180145bc0, SpaceShipDesignDeleteRoomCells:
  - Validate read-only state and polygon as above.
  - Preflight CanSubtractRoomBoundary for EVERY room on the selected deck,
    including roof types. Reject all changes if any preflight fails.
  - Subtract the polygon from each room on that deck.
  - Keep the room ID if >=3 boundary points remain; delete the room if a changed
    boundary has <3 points. This code never allocates split room records.
  - VerifyDetails and return true, even when no room boundary changed or no
    room array exists for the design.

AuData13.dll 0x180145f00, SpaceShipDesignDeleteRoomCompletely (the lower-level
-2 polygon operation, NOT the recovered Delete Room toolbar command):
  - Validate read-only state and polygon as above.
  - For EVERY room on the selected deck, test DoesIntersectRoomBoundary with
    the polygon. A successful test deletes the entire room, including roofs.
  - Multiple room records may be removed by one cell polygon.
  - There is no CanSubtract preflight because no partial geometry is retained.
  - VerifyDetails and return true, including no-op cases.

DoesIntersectRoomBoundary (0x180170cf0) is itself a raster test: fill the old
boundary, then return ZeroBoundary(cell)'s change result. Do not substitute
QPolygonF edge contact tests. Merely sharing a surviving edge is not the same
as removing occupied raster area.

The actual Delete Room UI follows the separate point-selection chain in
CONTROL-MAPPING.txt. DaSpaceShip::DesignDeleteRoom (AuAtom13.dll 0x1803e3d80)
uses InsideRoom to find a persistent room ID, then DgData::SpaceShipDesignDeleteRoom
(AuData13.dll 0x180145a30) checks read-only state, deletes the first matching
room ID, verifies details and returns true. A missing room returns false.
This route removes one selected record without a cell-polygon subtraction test.
Exact InsideRoom behavior on shared edges remains a separate hit-test concern.

4. Whole-room type change and a confirmed original defect
---------------------------------------------------------
AuAtom13.dll 0x1803e3a50, DaSpaceShip::DesignChangeRoomType:
  Check CanDesignBeModified, call InsideRoom(cursor, &roomId), require ID != 0,
  then call DgData::SpaceShipDesignChangeRoomType. Successful mutation
  invalidates design analysis and path caches.

AuData13.dll 0x1801447c0, DgData::SpaceShipDesignChangeRoomType:
  - Reject read-only, missing room, source roof types 0x16..0x18, unchanged type.
  - Reject if ANY room already has the source deck, requested type and source
    subtype. It does not merge the selected room into that target.
  - Copy source room, delete its old record, choose NextRoomId, set its type,
    then add the copy and verify details.
  - Deck, subtype and boundary are retained. ID is reallocated; it can be the
    same numeric value if the deleted ID is now the lowest available one.

The AuAtom wrapper ALWAYS returns false, including after a successful mutation.
This is not just a decompiler assumption: the common epilogue at 0x1803e3b34 is
XOR AL,AL followed by RET (assembly captured alongside the pseudocode).
Consequently FillRoomCell's success-driven modified-state update is not reached
through this wrapper. Other notifications may still update the visible model.
A future implementation should choose sensible success reporting explicitly;
do not silently use this defect as the intended painting contract.

The related Room Number change has its own data operation at AuData13.dll
0x180144520, SpaceShipDesignChangeRoomNumber. It rejects an unchanged subtype
or an existing same-deck/same-type/target-subtype record, then copies, deletes,
reallocates the persistent ID, sets subtype and adds the room, followed by
VerifyDetails. Unlike ChangeRoomType, it has no source-roof exclusion. This
corroborates the distinction between the visible Room Number and persistent ID.

5. Geometry machinery: one raster, one boundary
-----------------------------------------------
Relevant AuData13.dll exports:
  0x180172c30 DnRoom::IntersectRoomBoundary
  0x18016f4f0 DnRoom::CanSubtractRoomBoundary
  0x180173f30 DnRoom::SubtractRoomBoundary
  0x180170cf0 DnRoom::DoesIntersectRoomBoundary
  0x1801681f0 DnFloorBuffer8::AddBoundary
  0x180177770 DnFloorBuffer8::ZeroBoundary
  0x18016fc70 DnFloorBuffer8::ChaseBoundary
  0x180170770 DnFloorBuffer8::CornerEdgeVertexTest(x,y)
  0x180170990 DnFloorBuffer8::CornerEdgeVertexTest(x,y,incoming)
  0x18016f740 DnFloorBuffer8::CenterEdgeVertexTest

The buffer contains 516 * 516 bytes (0x41010), initially zero. XY vertices map
to indices round(coord / 1.41421356225) + 256. Indexing is x * 516 + y.
One full grid cell spans 4 buffer steps, while a saved half-grid unit spans 2.
Corners are 0 modulo 4 around the origin; cell centers are 2 modulo 4 on both
axes. AddBoundary/ZeroBoundary walk edges with integer sign steps and scanline
fill their interiors. This assumes horizontal, vertical or 45-degree edges
from the original cell vocabulary; it is not a general arbitrary-edge raster.

AddBoundary(boundary, marker):
  The old boundary is added with marker 1. The incoming polygon is added with
  marker 2. For a visited sample smaller than the marker, add the marker:
  the resulting values are 1 (old only), 2 (new only), 3 (both).
  Rasterization includes boundary samples and special corner/center scanline
  cases. The second call reports success only with at least one value-2 visit
  and at least two value-3 visits. Thus unchanged and disconnected paints fail;
  one-point contact alone is insufficient. Raw raster visits, not polygon area,
  govern this condition.

IntersectRoomBoundary fills old with 1, adds new with 2, and on success calls
ChaseBoundary(..., false). It replaces the old boundary only when tracing
succeeds and AuPointArray equality reports a different boundary.

ZeroBoundary(boundary):
  Mark the erase perimeter with 0x56 and its interior with 9; clear interior
  samples; restore perimeter samples to 1 where surrounding occupied cells
  still require them. Remove unsupported perimeter samples using distinct
  corner, center, edge and diagonal-neighbor cases. Its return value measures
  removed occupancy after that boundary repair, not mere edge intersection.
  The detailed scanline and neighbor predicates are preserved in the raw
  0x180177770 decompilation. They remain essential for an exact port.

CanSubtractRoomBoundary:
  Reject an old boundary with <3 points. Fill old with 1, ZeroBoundary(erase).
  If no occupancy changes, return true. Otherwise return
  ChaseBoundary(candidate, originalZ, true), without modifying the original.

SubtractRoomBoundary:
  Same raster operations, but an unchanged erase returns false. Trace with
  true; replace the boundary only if the trace succeeds and it differs.
  A fully erased room traces successfully with an empty output array.

ChaseBoundary(out, z, requireAllCorners):
  - Clear out. Scan occupied grid-corner sites at steps of 4, recording bounds
    and counting sites accepted by CornerEdgeVertexTest(x,y).
  - Return false for any site where this test reports -2 (ambiguous/invalid).
  - Find an initial outgoing edge in scan order and trace one outline.
  - Direction indices 0..7 have raster increments:
      (4,0), (2,2), (0,4), (-2,2), (-4,0), (-2,-2), (0,-4), (2,-2).
    Diagonal steps toggle whether the next vertex is a corner or cell center.
  - The corner-with-incoming overload searches from (incoming + 3) modulo 8,
    descending cyclically for seven candidates. Center selection requires an
    unambiguous outgoing edge. Missing/invalid edges (-1/-2) reject tracing.
  - Append vertices when direction changes, using
    (index - 256) * 1.41421356225 and the supplied z.
  - Reject when a visited point falls on an already emitted segment, except
    the original start. A 10,000-step guard bounds the trace loop.
  - For requireAllCorners=true, the count of reached corner sites must equal
    the count from the initial scan. For false this equality is not checked.
  - Normalize the duplicate/start vertex where the closing direction agrees;
    a nonempty successful boundary must have at least 3 vertices.
  - An empty raster is a successful empty result.

INFERENCE from the all-corners check and single-output representation:
  Erasure that leaves separate islands or introduces a hole normally fails
  preflight instead of splitting the room or storing inner rings. Point-pinched
  shapes can fail the corner/center ambiguity or self-contact checks. These
  are algorithmic conclusions awaiting controlled old-client fixtures.

INFERENCE requiring particular care:
  Addition traces with requireAllCorners=false and has no representation for
  inner rings. If adding cells encloses a void, an outer boundary trace can
  fill that void in the resulting room. Do not claim this as old-client-tested
  behavior yet. The raw checks, not a presumed topological policy, are authority.

6. Equipment reconciliation
----------------------------
After successful room operations, SpaceShipDesignVerifyDetails (AuData13.dll
0x18014b3f0) processes details in existing order through SpaceShipDesignTestDetail
0x18014a730 and DnDetail::IsValid 0x18015c9d0. Valid records may change type or
room ID; invalid records are removed. Later checks see earlier corrections and
deletions. Even an empty erase invokes this pass. Equipment has its own deck
limit (abs(deck)<=42), independent of the paint-deck range. The full recovered
rules and 143 original placement definitions are in EQUIPMENT-RECONCILIATION.txt.

7. Native port contract and safety guards
-----------------------------------------
Geometry and equipment changes commit together. Working boundaries retain
ordered doubles between strokes; do not quantize to saved packed bytes after
each edit. Empty source room records are excluded from authoring/reconciliation
lookups, matching the original loader's discard behavior (FORMAT.txt).

The port preserves exact point/order comparisons rather than Qt fuzzy equality.
AuMath13.dll_geometry_segment_tests.txt establishes boundary self-contact at
distance <=1e-5 feet from emitted open-array segments, with division by segment
length twice. Preserve that operation order and the 10,000-step trace guard's
final tests. CanSubtract accepts unchanged occupancy and full erasure; Subtract
reports unchanged as false and successful full erasure as an empty polygon.

Before rasterization, reject fewer than three points, nonfinite coordinates,
unsafe buffer coordinates (including a two-sample neighbor margin), and edges
that are neither axis-aligned nor 45-degree after raster rounding. The original
sign-step loop can fail to terminate on arbitrary edges. These guards reject
unsupported input explicitly; they never approximate it. Expanded ellipse roofs
may therefore block partial erasure on their deck. Out-of-buffer reads return
zero defensively. Failed operations leave the design unchanged and distinguish
errors from ordinary unchanged geometry. Unknown vehicle footprints likewise
reject an edit atomically rather than guessing.

room_raster.py is the executable integer quarter-grid reference. Thirteen
fixtures in room-raster-fixtures.json include the enclosed-void add result
predicted above; these are reconstructed results, not old-client saves.
TESTING.txt centralizes reference coverage, native harness commands and the
controlled old-client comparisons still needed for end-to-end parity.
