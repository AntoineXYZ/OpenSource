2016 building versus spacecraft design restrictions
===================================================
Recovered 2026-10-04 through read-only Ghidra MCP, with explicit DLL names.
Implementation scope: spacecraft editing only. Building mode is documented for
later, as requested. No build or original-client experiment was run.

Evidence
--------
pseudocode/mode-restrictions.txt contains the new PE-exported function captures
and assembly checks. Existing captures of DnDetail::IsValid, FillRoomCell,
DeckMinLimit/DeckMaxLimit and SpaceShipDesignTestDetail complete the paths.
CONTROL-MAPPING.txt records the spacecraft room tools and their Qt handlers.
Decompiled local names/types are reconstructions, not original source.

The environment mode byte at +0x3b0 is 1 for spacecraft, 2 for buildings.
These are different authoring paths; building rules must not be applied just
because both formats use DnRoom and DnDetail records.

1. Three distinct deck limits
-----------------------------
Grid navigation, BOTH modes: -41 through 41 inclusive.
  DaAtom::DesignDeckAbove/Below (AuAtom13 180207150/180207190) call the plane's
  MoveUp/MoveDown (1802ff0e0/1802feff0). Up rejects destination >=42; down
  rejects destination <=-42. Assembly confirms JGE/JLE after signed compares.
  These methods do not call the environment's room-paint deck limits.

Spacecraft room painting: -28 through 28 inclusive.
  DaDesignEnvironment::DeckMinLimit/DeckMaxLimit (1802f8170/1802f80e0) return
  -28/+28 in mode 1. FillRoomCell (1802f8ed0) checks these only when adding
  cells. Erasing cells and the separate whole-room type-change path bypass
  this check. Erasing imported geometry outside the paint range remains valid.

Equipment validation, BOTH modes: -42 through 42 inclusive.
  DnDetail::IsValid (AuData13 18015c9d0) rejects abs(deck)>42. This data-level
  rule is deliberately wider than navigation. A hull hatch/top turret on deck
  29 can attach to a spacecraft room on deck 28; a new room on deck 29 cannot
  be painted. Negative spacecraft decks are not building basements.

Correction in this pass: the viewer previously clamped navigation to +/-28.
Its deck arrows and displayed-deck clamp now use +/-41.
The room painter and equipment validator keep their separate recovered limits.

2. Room types and roofs
-----------------------
The spacecraft room-paint palette exposes types 1..21 except 12. See the
original Qt-handler list in CONTROL-MAPPING.txt. Type 12 has no recovered
paint action. The current palette already matches those twenty tools.

Gabled, hipped and round roofs are types 22, 23 and 24. They have their own
three-point command, not ordinary room-cell painting. CreateRoof (AuAtom13
1802f7dd0) mutates only when mode==2. The building data route (AuData13
BuildingDesignAddRoof, 18012c5e0) rejects a vertex whose OnDeck is negative,
checks every XY vertex against the site's limit, and allocates a new room
number for the roof's deck/type. Roof overlap is handled separately from
ordinary room-cell subtraction.

EditCell now accepts only the recovered spacecraft room tools or -1 (erase).
This is the offline authoring API enforcing the UI vocabulary. The old generic
SpaceShipDesignAddRoom data method itself did not whitelist room types; do not
mistake the new guard for a newly discovered check in that low-level function.
Loaded roofs/unknown records remain readable/renderable/serializable. Their
presence does not turn a ship into a building or silently remove its records.

3. Equipment differences
------------------------
BuildingDesignTestDetail (AuData13 180133a90) passes false as IsValid's final
spacecraft argument. SpaceShipDesignTestDetail (18014a730) passes true.
The mode-dependent branches in IsValid are:

  - Outdoor placement (-8): flag pole 100 and light pole 142 must be on deck
    zero and outside every room. The final outside-room test permits this
    only for buildings. They cannot be placed anywhere on a spacecraft.
  - Troop station 141 (placement -10): buildings can place one outside all
    rooms. Spacecraft require a room interior; walls and fuel cells fail.
  - Exterior floor placement (-5), including hull hatches and top/bottom
    turrets: buildings reject deck<-1, and reject deck<1 when there is no
    containing room below. This is the exact condition; the debug message
    says "must be above ground in building" but is less precise than the code.
    Spacecraft do not have this extra ground check. Both modes still require
    exactly one containing room, counting the current deck and deck below.
  - In the other-placement branch, buildings reject negative-deck objects
    classified by DnDetailType::IsHullOpening (180032640). This catches wall
    hull doors/openings (types 3, 9, 50). Hull hatches use the floor branch
    above. Side turrets are not classified as IsHullOpening. Spacecraft skip
    this ground check.

The existing native validator already implements spacecraft behavior for
these branches. This pass adds an explicit outdoor-pole rejection at the
authoring entry point, before replacement and the same-type no-change shortcut.
This also rejects a repeated placement over an imported pole, preserving the
existing design. Loading/saving alone does not invoke this new guard.

The existing room/bridge exceptions, berth rooms, vehicle-bay footprints,
stair coverage, spacing, station limits, emitter limits and room-count tests
are shared rules. They remain active. Berth help now says barracks and officer
cabin, matching the spacecraft palette rather than calling type 1 an apartment.

4. Building floor limits (documentation only)
---------------------------------------------
BuildingDesignMinDeckLimit (AuData13 180131490):
  industry 11 or 12: -5
  industry 50:       -8
  industry 51:       -1
  every other ID:     0

BuildingDesignMaxDeckLimit (180131180) first handles these fixed cases:
  industries                                      Maximum deck
  0, 1, 2, 10, 51, 114, 129, 130                   0
  11, 12                                           2
  70, 85, 88, 113, 127                              1
  87, 126                                          5
  111                                              4
  112, 128                                         3

Otherwise it reads the industry rule byte at +0x15 in the original GD record.
It defaults to 99 when no industry record is found. The material-dependent
result is below; column headings are original commodity IDs. Parenthetical
names are the matching modern-source enum names, not recovered 2016 symbols.

  Rule     86 (Wood)  48 (Lumber)  76 (Stone)  51 (Metal) 146 (Magmium) Other
   0            0          0           0          0           0         0
   1            0          1           1          1           1         1
   3            0          3           3          3           3         3
   7            0          3           7          7           7         7
  15            0          3           7         15          15        15
  31            0          3           7         15          23        31
  32, 33        0          0           0          0           0         0
  34            1          1           1          1           1         1
  all other     0          0           0          0           0         0

The building designer's DeckMaxLimit passes commodity 145 (modern Vulcium),
so its editing ceiling uses the Other column, after the fixed industry cases.
Do not use these building limits to constrain spacecraft decks.

5. Building XY/site limits (documentation only)
-----------------------------------------------
Spacecraft use abs(round(x/2.8284271245))<=120 and the same for Y, with round
half away from zero. These packed half-grid limits already exist in EditCell
and equipment placement. The visible 80-cell-wide grid is not the edit limit.

BuildingDesignAddRoom (AuData13 18012c8f0) obtains the industry and deck,
computes IndustrySiteRadius, and checks each raw vertex. DnBuilding's static
IsValidGridCoord (180159bd0) requires abs(x)<=radius and abs(y)<=radius; for
industries 34, 62 and 85 it additionally requires y<=0 (waterfront boundary).
Unlike the spacecraft test, the raw XY bounds are checked before packing.

IndustrySiteRadius (18013b570) starts with TerrainLevelRadius (180046d70):
  industry             float radius in feet (decompiler decimal rendering)
  20                   26.24672
  30, 32               42.650917
  31, 50, 51           32.8084
  66, 67               49.2126
  113                  65.6168
  114                   9.84252
  other                 0

A zero terrain radius falls back to ConstructionSiteRadius (180135570):
the original GD industry record's first byte times 3.28083989501312; missing
industry yields zero. Industry 50 expands below deck -1 by
(-1-deck)*5.656854249, capped at ConstructionSiteRadius. A future building
port must retain the original float values and GD site/rule data; modern
industry defaults are not evidence of the original 2016 data values.

Verification and limits
-----------------------
New manual native cases cover all twenty room tools, rejection without
repainting for roof/reserved/unknown types, outdoor poles, troop stations,
negative-deck hull openings and deck-29 hull attachments. Existing tests retain
paint +/-28, grid XY +/-120, erasure outside the paint limits, and loaded roofs.
See TESTING.txt for the manual navigation check and harness commands.

Non-build checks run after these changes: all 8,328 original-sample equipment
records passed the existing categorical placement audit, and all three
reference save checks passed with their recorded hashes. These Python checks
do not execute the changed C++ or replace the pending native/UI tests.

This is static recovery, not an exhaustive original-client interaction test.
No building UI, building file writer, publishing checks, or new world-rendering
behavior is introduced. The .ship reader/writer and save preparation are not
modified; the previously verified save-byte behavior is unaffected.
