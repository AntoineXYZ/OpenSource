Recovery validation
====================

Build policy and evidence limits
--------------------------------
The user builds manually. The assistant must not run a compiler or client build.
Native harnesses below are outside game targets and have not been built/run by
the assistant. Synthetic fixtures test recovered algorithms; they do not prove
original-client runtime or visual parity. The user verified the viewer, cell
editing and fresh designs. The restored panel still needs native UI comparison.

Reference checks (repository root; no build)
--------------------------------------------
  python3 -B research/legacy-spacecraft-2016/cell_shapes.py --self-test
  python3 -B research/legacy-spacecraft-2016/room_raster.py --self-test
  python3 -B research/legacy-spacecraft-2016/inspect_vehicle_bounds.py --self-test
  python3 -B research/legacy-spacecraft-2016/tests/check_ship_writer.py
  python3 -B research/legacy-spacecraft-2016/tests/check_detail_placements.py \
    '/path/to/design.ship'

Recorded coverage: cell shapes passed 2,156 independent half-plane checks,
8,624 translated checks, every byte mask, literal bits, ties and negative seams.
The raster reference checked 19,160 occupancy/boundary points, 220 complete
erasures, 105,840 interior subtraction samples, all 16 scanline predicates and
13 topology fixtures. All 84 original sample room boundaries traced; all
8,328 details passed the categorical placement audit. That audit does not test
full spacing, vehicle geometry or native reconciliation. Original asset checks
covered 143 detail definitions, 15 vehicle commodities and 111 unchanged PNGs.

Sample baselines (full hashes and per-deck counts: sample-inspection.json):

None has empty/ellipse-control rooms. Version 0/1 coverage is synthetic.

Reader fixtures use Qt's own Qt_4_0 writer and cover versions 0/1/2, every
truncation, exact EOF, UTF-16/null strings, count/size limits, atomic failure,
signed coordinates, normalization and ellipse expansion/degeneracy. Geometry
checks exact fixture outputs, 3,072 cell outputs and unsupported-input guards.
Edit/detail fixtures cover room keys, ID reuse, competing repaint, atomicity,
empty/full erasure, roofs, coordinate limits and equipment correction/removal.

For full native/Python record parity, substitute an original sample path:
  python3 -B research/legacy-spacecraft-2016/tests/compare_native_reader.py \
    /tmp/native_ship_reader '/path/to/design.ship'
Multiple sample paths are accepted. /tmp/native_ship_edit also accepts sample
paths for in-memory new-deck edits and reconciliation; it never writes them.
/tmp/native_ship_reader '/path/to/design.ship' emits a complete JSON dump.

Native saving checks (user builds manually)
-------------------------------------------
The reference save check above audits the three recorded sample paths; pass
other paths explicitly if the originals are elsewhere. It has passed on all
three samples: Antiflux is byte-identical and Galatine changes 11 old vehicle
ID bytes. Star Driver normalizes 18 vehicle IDs, adds the transporter module
entry and puts equipment in the original designer's deck/room/ID order.
This is a Python reference check, not a claim that the C++ serializer has run.

Build this isolated harness manually; it is not a client build target:

  c++ -std=c++11 -fPIC -no-pie -Isrc/lib/data/designs \
    research/legacy-spacecraft-2016/tests/native_ship_writer.cpp \
    src/lib/data/designs/aulegacyship.cpp \
    src/lib/data/designs/aulegacyshipsave.cpp \
    $(pkg-config --cflags --libs Qt5Core Qt5Gui) -o /tmp/native_ship_writer

  /tmp/native_ship_writer --self-test
  python3 -B research/legacy-spacecraft-2016/tests/check_ship_writer.py \
    --native /tmp/native_ship_writer '/path/to/original/sample.ship'

The Python comparison gives the already-built harness a temporary output path,
compares its entire output against the independent reference, then removes the
temporary file. It never overwrites sample files or starts a build. Multiple
sample paths are accepted; omitting paths uses sample-inspection.json.

Compare a single input against its actual 2016 designer re-save:

  python3 -B research/legacy-spacecraft-2016/tests/check_ship_writer.py \
    '/path/to/tl20StarDriver.ship' \
    --legacy-save '/path/to/tl20StarDriver 2016 designer save.ship'

This reference comparison has passed on the supplied files. It reports the
identity fields, projects only the captured design ID and architect ID/name,
and compares every byte. No equipment order, module data or geometry is copied
from the original save into the expected output. Add --native with the already
built harness to also check the actual C++ Save path. The original session's
random avatar ID cannot be reproduced by retaining the source author; see the
architect identity investigation in FORMAT.txt.

The native tests cover a fixed 104-byte wire oracle, exact v0/v1 upgrades,
original default modules, record order, null/empty/surrogate UTF-16, fallback
names, all normalization rules, negative XY/decks, signed rounding ties,
working boundary precedence, ellipse compression, empty room removal,
invalid geometry/counts and atomic file replacement/failure. Preparation tests
cover signed detail ordering, transporter consoles versus pads, multiple pads,
negative/multiple decks, room numbers, custom selections, duplicate/stale keys,
empty/orphan rooms, bay units/emitters and module-map collision/growth ordering
at 8/9, 64/65 and 512/513 entries. The fixed hex oracles and module-order digests
have been checked independently in Python. The native
harness itself has NOT been compiled/run by the assistant.

Manual UI and original-client comparisons
-----------------------------------------
Launch AuSceneClient -legacy-spacecraft [file] or use the designer chooser.
The VS Code "Legacy spacecraft viewer (already built)" profiles have no build
task. Paths must match the executable's platform (Windows uses C:\ paths).

Check the right-docked palette, F6 hide/float/redock, icon availability without
legacy DLLs, dark controls, selected tools, pan/zoom/fit and record inspection.
The Fit view button must be absent; the F shortcut and automatic fitting remain.
Check the original design-disk icon appears at the left of the F6 panel title,
both docked and floating; the application window icon must remain unchanged.
Drag and double-click the title, use Dock/Float and close, then reopen with F6.
The bottom status bar and cursor-coordinate readout must be absent in both
launch paths. Rejected edits and grid warnings must appear in the tools panel;
the inspector must still show current deck/Z after switching decks.
Check New and loaded designs show a finite 80x80-cell grid, with no lines outside
+/-226.27416996 feet and brighter lines every ten cells. Exercise all four grid
directions at the edges; disabling them leaves the square boundary and labels.
Fore/Port Fore/Starboard Fore must be at the top; Aft/Port Quarter/Starboard
Quarter at the bottom; Port left and Starboard right. Fit must leave all labels
visible, and zoom must preserve their text size. The grid's scrollbars and top
summary strip must be absent; middle-drag must still pan. The title's dirty
asterisk and discard confirmation must still work after painting/header edits.
Check room labels (e.g. Engine Room 1/2/3): name and subtype+1, first-boundary
vertex anchor, original label color and black shadow. Pan/zoom must move their
anchors without scaling the text. Switch decks, paint/grow/repaint/erase rooms,
and start a fresh design; labels must follow the current geometry without stale
copies. Clicking/painting through a label must still reach the room or detail.
Confirm the File/View menu bar is absent and Escape exits from the deck and
docked/floating panel, offering Save/Discard/Cancel when modified. Ctrl+N, Ctrl+O,
Ctrl+S, F and F6 must still work with the panel hidden. Escape in a file dialog or
discard prompt must dismiss that dialog rather than exit the designer.
Deck arrows must stop at -41/+41. New rooms must be rejected outside -28/+28,
but cell erasure remains available there. Paint a Hold on deck 28, move to 29,
and place a hull hatch or top turret over its interior; it must attach to the
room below. Room painting on 29 must fail without deleting that attachment.
Check the deck buttons in both floor-plan and rendered cutaway modes.
Outdoor flag/light poles and roof tools must not appear in the spacecraft
palette. Native_ship_edit/native_detail_edit add mode-restriction cases; they
have not been compiled or run by the assistant. See BUILDING-VS-SPACECRAFT.txt.
Room Number wraps 1..256; minimum TL displays 32..1.
New defaults: streamline enabled, armor 0, minimum TL display 1. Loading
must preserve design settings without marking dirty; it assigns a fresh working
design ID. Disabled tools must do nothing.

Test New/Open/Exit/close with Save, Discard and Cancel, failed loads preserving
edits, and last-directory persistence (successful opens/saves; folder fallback).
Use the existing Save icon: the original always-prompt save dialog must open.
Test new and loaded designs, filename suffixes, overwrite confirmation, Cancel,
read-only destinations and invalid geometry. Only a successful save clears the
dirty asterisk; a cancelled/failed save during exit must keep the editor open.
Paint cells and place/rotate every available equipment type, save to a copy,
reopen and check room numbers, decks, IDs, positions and 3D appearance. Repeat
Save without editing and compare bytes. Open the current file while dirty,
choose Save to that same path, and verify the newly saved geometry loads.
Load saved copies in the original 2016 client as the final interoperability
check. Do not infer full original-session parity solely from a round-trip:
the original world-backed workflow may assign different design/architect IDs.
In a fresh process, the initial blank design must have ID 20000 and the first
successful import 20001. Verify that header, rooms and equipment all carry the
same working ID. Save twice: the ID must not change. Cancel New/Open and try a
failed load: none must consume an ID. The next successful New/import must use
20002. Restart both designers and perform the same import sequence before
comparing: design IDs should now agree, leaving only architect identity.
Add transporter pads in two room numbers on different decks and save. Confirm
each group gains one header module; adding only a console must not add one.
Remove the final pad and save again; its module must disappear. Remove a bay
or change its Room Number and verify stale/default module reconciliation.
Check embedded entry/exit, music restoration, reopening Legacy and subsequent
Modern entry; the two designers cannot be switched directly while open.

For original parity, save controlled before/after files in the old client:
adjacent/contained/disconnected/corner-touch paints; competing type/subtype;
edge/full/bridge/hole erases; a closed loop; diagonal cells and negative seams;
XY +/-120 and deck +/-28 limits. Compare IDs, boundaries and equipment changes,
not just appearance. Whole-room hit tests and type/number reassignment remain
future comparisons; PAINTING-RULES.txt records their distinct original paths.

Rendering validation (user builds manually)
------------------------------------------
The rendering work did not run a compiler, build system, or native client.
The cell-shape and room-raster Python reference checks above passed again.
All 62 atlas rectangles in the new renderer were independently compared
with the surviving AuBodyRenderWidget::ShipTexture table and matched.
These checks do not establish native rendering or visual parity.

The CPU mesh harness can be built by the user without an OpenGL context.
It stubs only the resource-model importer; it checks the real surface,
procedural equipment and stair code, not 3DS loading or vehicle materials:

  c++ -std=c++11 -fPIC -no-pie -Isrc/lib/data/designs \
    -Isrc/lib/designer/legacy \
    research/legacy-spacecraft-2016/tests/native_ship_mesh.cpp \
    research/legacy-spacecraft-2016/tests/native_resource_stubs.cpp \
    src/lib/designer/legacy/aulegacyshipmesh.cpp \
    src/lib/designer/legacy/aulegacyshipequipment.cpp \
    src/lib/designer/legacy/aulegacyshipstairs.cpp \
    src/lib/data/designs/aulegacyship.cpp \
    src/lib/data/designs/aulegacyshipdetails.cpp \
    src/lib/data/designs/aulegacyshipgeometry.cpp \
    $(pkg-config --cflags --libs Qt5Core Qt5Gui) -o /tmp/native_ship_mesh

  /tmp/native_ship_mesh

It checks single/stacked-deck area, hidden hull suppression, open-below
over ordinary/fuel/missing decks, concavity, signed deck heights, same-type
different-number room partitions, inherited open-below partition ownership,
square/diamond hatch aperture areas, small doors and full-span wall openings,
finite normals/positions across every
spacecraft room type at all eleven armor settings, every nonempty cell-mask
shape's area, invalid/zero-area boundary rejection, top/bottom turret cut areas,
dome normals/depth, side turret profiles and frame UVs. It has not been built or run.

After a manual client build, compare the three sample ships and controlled
one/two-deck fixtures with the original client. Check Render Mode in its
original palette position, unchanged dp_RenderMode icon/tooltip, and repeated
floor-plan/solid switching. Check the floor-plan camera and selected tool
survive toggling; selecting Paint/Erase/Inspect returns to the floor plan.
Check left-drag orbit, middle/right/Shift-drag pan, wheel zoom, F/Home fit,
resize, F6 docking/floating, and entry/exit through both launch paths.

Check armor 0..10 room silhouettes and transparent window frames; bridge,
lounge, captain's cabin and weapon-bay glass floors/tops; neighboring room
partitions; fuel rooms; negative decks; open-to-below and gravity-well rooms.
The cutaway is an added orbit-inspection aid, not a recovered original mode:
move the selected deck up/down and confirm upper surfaces are clipped while
the current deck's floor/lower walls remain. Test hatch/door/opening fixtures
and read the inspector's explicit rendering limitations. Animated door states
and full original visual parity require further work.
