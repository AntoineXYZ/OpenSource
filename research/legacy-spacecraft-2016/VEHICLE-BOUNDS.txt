Original 2016 vehicle bounds used by room-edit reconciliation
============================================================

vehicle-bounds.json is generated by inspect_vehicle_bounds.py from the original
Fresh 2016 GD and AuModelRes13.dll. It covers all fifteen CIDs recognized by
DbCommodity::IsVehicle at AuGlobal13.dll 0x180008eb0. Eleven have embedded model
assets; four use the original missing-model fallback. No DLL was loaded or
executed, no asset was extracted to disk, and no build was run.

Data path and precision
-----------------------

The inspector reads the original GD room and commodity records, following the
explicit QDataStream reads in DbCommodity::Rx. The commodity's original model
path is used to locate its Qt resource inside AuModelRes13.dll. Seven resource
registrations and their 14-byte tree entries identify the original embedded
payloads; Qt-compressed payloads are decompressed in memory with length checks.
The report retains GD/DLL/asset hashes and included/excluded object names.

The original load chain is AuGL13.dll:
  0x180013bc0 Au3dsGLSLModel::Load(QFile&, double): detects .3dsX as format 3.
  0x180015b70 LoadEditorChunk: folds included object extents into model bounds.
  0x1800173d0 LoadMeshChunk: parses chunks in order and projects each float vertex
      through the object's double matrix before computing double min/max.
  0x18001c640 LoadVertexListChunk: loads the stored IEEE binary32 vertices.
  0x1800170e0 LoadMatrixChunk: format 3 scales existing vertices by double 1/12.
  0x180024b40: casts EACH scaled coordinate back to binary32.
  0x180021640: inverse-matrix vertex projection also stores binary32 coordinates.

All matrix chunks in the three present .3dsX assets are exactly identity with
zero translation: Space Rocket has 20, Submarine 64, Sailboat 10. Their inverse
branch is therefore not taken. The eight .3dsN vehicle assets have no matrix
chunks. The inspector checks these conditions and rejects other transforms;
it does not approximate their inverse. Scaling remains a matrix-chunk event,
preserving chunk order rather than applying an extension-wide final scale.

TestForExtents at 0x180026330 excludes empty objects, names starting '-', valid
stations and weapon markers. TestForStation at 0x180026670 reads a two-character
hexadecimal field using name.mid(2, 2), then requires a nonzero low byte. The
length argument was absent from the decompiler's guessed call signature; the
saved assembly at 0x180026735 explicitly sets R8D and R9D to 2. This matters for
long Symmetrica names such as @0405074. TestForWeapon is at 0x180026b00.

DnDetail::IsValid and DnDetailType::MinPlacementSpacing both compute (max-min)/2
in double, then narrow each XY half-size to float before promoting it back to
double for rectangle construction and rotation. MinPlacementSpacing's captured
body explicitly assigns fVar13/fVar14 from those half-dimensions, then constructs
its corner points from the promoted floats. The JSON retains BOTH half_xy (the
intermediate double) and half_xy_float32 (the value used by both callers); the
double table must undergo that float narrowing before either calculation.

Original missing-resource behavior
----------------------------------

The GD references these absent paths:
  CID 54  :data/mMineMachinery.3dsX
  CID 70  :data/mCommercialShip.3dsX
  CID 71  :data/mNavalShip.3dsX
  CID 103 :data/mTank.3dsX

Their resource names are absent from AuModelRes13.dll and every original DLL,
EXE and RCC checked (20 binaries in this client copy), in ASCII, UTF-16BE and
UTF-16LE. Qt resource name tables are not compressed. The report includes each
checked binary's SHA-256. The script refuses the missing-resource fallback if
one of those names appears in another binary and needs further investigation.

Load(QString) at AuGL13.dll 0x180014330 returns false when QFile::open fails.
CreateGeometry at 0x180010860 then destroys the failed model and returns null.
DnDetail::IsValid initializes its min/max to zero before this call and retains
those zeros for a null result. Zero half-extents for these four entries are
therefore recovered original behavior for this client copy, not invented model
dimensions. A different original resource set must be re-inspected.

Read-only evidence is collected in pseudocode/vehicle-bounds-loader-evidence.txt.
The existing IsValid/MinPlacementSpacing and commodity Rx captures provide the
caller/schema evidence. Nothing here implies the original missing assets have
been reconstructed.

Verification
------------

  python3 -B research/legacy-spacecraft-2016/inspect_vehicle_bounds.py --self-test
  python3 -B research/legacy-spacecraft-2016/inspect_vehicle_bounds.py \
    "/mnt/c/Users/Celarious/Desktop/Shores of Hazeron/Fresh 2016"

Synthetic chunks verify per-coordinate float rounding, original chunk ordering,
the no-matrix case, long station identifiers, weapon/hidden exclusions, and the
unsupported-transform rejection. Reinspection of the original client reproduced
vehicle-bounds.json exactly for all fifteen entries. This is static algorithm
replay over original assets, not execution of the 2016 model loader.
