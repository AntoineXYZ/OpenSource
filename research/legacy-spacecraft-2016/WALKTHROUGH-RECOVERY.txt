2016 designer walkthrough recovery
==================================
Captured 2026-10-04 by read-only Ghidra MCP. Addresses below are virtual
addresses in the original 2016 client. Pseudocode excerpts are preserved in
pseudocode/walkthrough-mode.txt. No original executable was run or modified.

Mode and spawn
--------------
Shores of Hazeron.exe 0x140244760 creates an offline world, a mode-1
DaDesignEnvironment, then a DaPerson named Human inside that environment.
The avatar is stood up and gets an identity transform translated by
GroundHeightAboveCG() along +Z. The ship uses its own identity transform.
There is no orbit-camera entry and no equipment-marker spawn in this path.

AuAtom13.dll:
  0x1802fced0 DaDesignPlane(owner) initializes gravity OFF, solid OFF.
  0x1802f9240 InitDesignPlane resets an existing plane to identity, gravity
              OFF, solid OFF, horizontal/vertical grids ON, diagonals OFF.
  0x1802077a0 DaAtom::DesignRenderModeToggle flips plane byte +0x3b8 only.
  0x180207390 DaAtom::DesignGravityToggle flips plane byte +0x3b0 only.
  0x1802f9cc0 IsRenderSolid and 0x1802f9af0 IsGravityOn read those flags
              for the calling avatar's own plane.
  0x1802fb550 ResetPositions stands all avatars at x=y=0, z=standing CG,
              reparents them directly to the studio, resets ship identity.

The render toggle does not move the avatar or change its camera orientation.
The original line drawing is also viewed through the avatar's scene camera.

Movement, gravity and collision
-------------------------------
  0x1802f91e0 DaDesignEnvironment::Gravity returns 32 feet/second squared.
  0x1803fa2a0 DaSpaceShip::IsPathBlocked returns false in the studio when
              the caller's solid-render flag is OFF. In solid mode it
              checks the ship's path model and door states.
  0x1803cfd20 CheckPeerJoin: in a studio, only solid-render avatars can
              become children of the ship when moving into/on its hull.
  0x1803cfc10 CheckChildExit: line mode forces an avatar out of the ship;
              solid mode leaves it aboard while IsInOrOnHull is nonzero.

The gravity button has a narrower effect than a universal flight switch.
This is confirmed through the final acceleration call chain:
  0x1802049a0 DaAtom::CreateEnvironmentQuery first computes ship-floor
              information for an avatar parented to a ship and ORs
              EB_Gravity (0x10000) when ship.Gravity() is nonzero.
  0x1803f4250 DaSpaceShip::Gravity returns 32 inside a designer environment.
  0x1802049a0 subsequently visits the designer branch. If IsGravityOn(owner)
              is false it returns WITHOUT clearing EB_Gravity previously
              supplied by the ship. If true, it sets the flag. If no parent
              ship exists it calculates floor distance to the design plane.
  0x18031be50 DaPerson::Acceleration adds DaCreature::Acceleration when
              EB_Gravity is present, except the administrator movement flag.
  0x1802e2e30 DaCreature::Acceleration calls DaAtom::Acceleration when
              IsAffectedByGravity permits it.
  0x1801ffd70 DaAtom::Acceleration suppresses gravity in a gravity well or
              when EB_Design is set and EB_Gravity is absent.
There is no further lookup of the toolbar's gravity flag in that chain.
Consequently normal ship interiors/on-hull retain gravity after boarding,
even with the studio gravity toggle off. The toggle controls gravity while
outside the ship, where the studio plane supplies the ground. Gravity wells,
ladder poses and being above an open hatch have their own movement rules.

The original ship-floor query subtracts 1/12 foot extra clearance and uses
a 0.25-foot ground-contact tolerance. Body height is pose-dependent, while
the person/animal branch of IsPathBlocked sends point locations to the path
model; the transformed-box branch serves other actor types. The local
capsule/triangle controller is an implementation approximation.

Ship membership and studio ground correction
-------------------------------------------
AuAtom13.dll 0x1803f9ab0 IsInOrOnHull queries the path cell at the person's
position: cell 0 is outside, 0x11 returns 3, 0x10/7 return 2, and other
nonzero cells return 1. This is a path-grid query, not a body-height test.
AuData13.dll 0x1801c3a10 PathCellTypeAt permits XY bounds expanded by
1.41421356225 feet and deck indices from lowest deck minus one through
highest deck plus one, then delegates to 0x1800723a0 CellTypeAt. The latter
uses HalfGridCoord XY and the integer deck to look up the path-cell hash.
Extending an authored room's roof range by the local capsule height is a
bounded approximation for roof jumps, not the original membership rule.

AuAtom13.dll 0x180219280 TickMovement corrects an avatar already below its
ground whenever EB_Gravity is set, CanBeUnderGround is false, and FallDist
is negative. It translates by GravityNormal * -FallDist and resets FallDist
to zero. Assembly 0x1802198d8 through 0x18021996f confirms the sign, which
the decompiler loses at the floating-point multiply. There is no previous
height/crossing test and no maximum correction distance. Thus an outside
avatar below the studio plane is pulled up when studio gravity is enabled;
a ship-parented avatar instead uses its ship-floor environment query.

Door opening while moving
-------------------------
0x1803fa2a0 calls DqDesignAnalysis::TestSpacecraftPath or AuPath::
TestSpacecraftPath with current door states and an output list of doors.
It then calls DaSpaceShip::OpenDoor for each returned door ID. Doors can
therefore open automatically when movement attempts approach them, subject
to the original access/path rules. The person default controls have no
separate E-to-open-door action; E is enter/exit console, ladder or vehicle.
Animation and door lifetime evidence are documented separately.

Controls and movement values
----------------------------
AuAtom13.dll 0x1800652e0 initializes the original person control table:
  Mouse motion: look up/down, turn left/right.
  W/S: forward/backward; A/D: strafe left/right.
  C/Z: move up/down.
  Shift: run modifier.
  Space: Jump. Brake in Zero-G or When Flying.
  Q: continuous forward movement.
  E: enter/exit console, ladder, mount or vehicle; drop rider/pick up body.
  U/right mouse: use item.
  F/left mouse: fire weapon/use item on target.
  X: prone/stand; Caps Lock: crouch.

AuGlobal13.dll 0x180079d00 InitDefaultHuman writes DNA words:
  92800d65 16711080 6a587782 82054654 72c254a2
Speed is the nibble at DNA +0x10 bits 8..11: 4, hence base speed 5 ft/sec.
AuData13.dll 0x1800d0050 DpBody::MovementSpeed uses pose factors:
  walk 0x26 -> 1.0; run 0x25 -> 2.5 (default-human 5 and 12.5 ft/sec).
AuGlobal13.dll 0x1800092c0 JumpForce returns speed+11 for a normal human:
  15 ft/sec. Creatures with the special jumping trait use speed*4+14.
AuData13.dll 0x1800cd730 standing pose 0x24 uses that upward jump vector.

These are body movement values, not a complete velocity integrator.
0x18031be50 applies acceleration, speed caps, directional factors and pose.
Forward follows head pitch in zero gravity; normal grounded movement follows
the floor. Ascend is unavailable in normal gravity unless in a gravity well,
water, flight or ladder pose. The input vector is normalized before applying
its acceleration. 0x180330690 makes braking in the designer very strong
(10000 on all three axes); 0x1802e9960 supplies pose/environment friction.

Camera
------
Shores of Hazeron.exe 0x140304340 sets scene perspective to pi/4 (45-degree
vertical FOV), height/width aspect in AuMatrix4x4's convention, and the
avatar's near/far values. AuAtom13.dll 0x1802f1450 SetupCamera uses:
  standing near = 3 feet; prone near = 1 foot; vehicle near = 2 feet;
  far = 297000000 feet.
The original 2016 function has no designer-specific near=1 branch.

Eye location and collision extents are procedural body/pose dependent:
  0x1802ea5c0 GroundHeightAboveCG -> CGHeight for a normal standing human.
  0x1802e4340 CameraOffset -> DpBody::CameraLocation.
  AuData13.dll 0x180183b00 CameraLocation selects a posed head's camera point.
  AuData13.dll 0x1801832a0 CGHeightStanding uses thigh/calf length, carriage,
              ankle bend and foot height.
SetupCamera also shifts longitudinally by near/2 minus head thickness.
No universal fixed eye-height/body-radius constant is established here.

Scope and compatibility
-----------------------
This recovery addresses character traversal, render/gravity semantics and
movement-triggered door operation. It does not implement the separate
user-facing path-checking milestone, transporter labels or floor-plan icon
sizes. Retaining an independent orthographic editing view, using fixed human
capsule dimensions, a shorter near plane or a modern velocity solver must
be described as local adaptations rather than byte-for-byte recovered logic.

Target health indicator and acquisition
--------------------------------------
AuAtom13.dll DaSpaceShip::RenderBodyStats 0x1804122a0 draws the targeted
ship's system health at the top. It draws no numeric HP text: the display
is a textured wrench bar, system icon, and NameWithEmpire below. The bar
fraction is SystemHitsRemaining / SystemHits. A fresh undamaged authoring
preview therefore uses the full bar without inventing a numeric HP total.

The caller, DaPerson::RenderScene 0x1803455c0, supplies width .275 and height
.05 (verified in assembly/data constants at 0x180345be9..0x180345c0a).
The ship scales height by .75, moves the bar left to 0 (horizontal screen
center), and sets bottom to 1 - height - .01. These are normalized screen
units with x scaled by viewport height/width. The icon is one bar-height
square, positioned 1.5 bar-heights left of the bar. The name is centered
under the combined icon/bar area with .005 normalized spacing at the
default 100-percent body-stat size.

Healthy bar RGB is (.2,1,.2); unused bar RGB is (.5,.35,.1). Below half
health, the filled part changes to (1,.7,.2); at <=.1 or with a visible
condition it changes to (1,.2,.2). The local designer has no empire, so
EXE 0x14012b690 returns neutral stance 1 and the name is RGB(192,192,192).
DetailSystem 0x1803e7a30 maps target detail 0 to SYS_Hull=4. Doors, hatches
and many furnishings also map to hull; command/control is system 0.

The bar is shown only outside top-down view when there is a retained target,
target level >0, and target distance in feet <=10*target level. EXE target
update 0x1403098d0 retains target ID, detail ID, location and level. Its worker
0x14032f800 runs every 200ms:
  no target: level/=2; clear target/location when it reaches zero;
  same target, same detail: level = level ? min(15,level*2) : 1;
  same target, different detail: level=min(15,level+1), replace detail;
  different target: replace ID/detail/location and divide prior level by 3.
Thus starting from no target, steady sight acquisition is 0,1,2,4,8,15;
loss from a fully acquired target decays 7,3,1,0 while retaining its last
location until zero. The maximum distance for the top bar is 150 feet.

SightTarget 0x180467020 and SightTargetDetails 0x180467140 are separate
from movement path cells. They intersect per-deck room boundaries, skip
open doors/openings, and inspect equipment using SightType/SightRadius
approximations before returning the detail ID. A mesh ray is a local
approximation; invisible movement obstacle boxes must not become HUD targets.
Detail IDs now reach the HUD with the original system/which mapping and
subsystem HP capacities. See WALKTHROUGH-SUBSYSTEM-TARGETS.txt for exact mappings,
sight eligibility, regression coverage and remaining intersection differences.

The shared game resource :/data/HudItems.png supplies the local HUD helper.
Original AuAtomRes13.dll resource registration RVA 0x1030 contains a 1024x64
atlas, PNG SHA256 00c655a71b343d9f56bd03dc91f7b25d7972a3c9fa7f432ff08cf8e103d87ca5.
The full modern atlas differs, but decoded RGBA comparisons confirm that
the wrench bar (x271,y34,w129,h10), hull icon (x832,y32,w16,h16), and shared
crosshair regions are identical. Both embedded and standalone client
startup register AuAtomRes. The user specifically prefers the existing
game crosshair, so the helper reuses that asset and its shared layout;
no separate crosshair texture extraction is required.

PaintShipTarget uses QPainter and the current overlay font; text rasterization
can differ from the original Windows font/GL texture path. Authoring HUD
contains no simulated damage and does not modify serialized Design data.

Game state and audio ownership
------------------------------
The original offline designer uses the ordinary client state and scene view.
Shores of Hazeron.exe 0x140213980 switches on the application mode at +0x18.
Mode 5 loads DgData::LoadBasicGameData from gp_AuGlobal's data object, calls
the designer-world initializer 0x140244760, then follows the same view setup
0x14020ebf0 and active-person selection 0x1403039b0 used by game mode 1.
0x14020ebf0 constructs AuView via 0x1402e1fe0 and installs it as the main
window's central widget. The designer world and avatar belong to the global
atom tree, and the avatar is selected through DgData::SetActiveUnit. There
is no isolated preview global or independent designer sound configuration.

2016 audio predates the modern AuSound class split: AuGLEffects owns both
render effects and audio. AuView::initializeGL at EXE 0x14030dab0 calls
AuAtomRenderInfo::InitializeGL(true) for its member at +0x6b8. AuAtom13.dll
0x18020f6d0 creates AuGLEffects at render-info +0x20, copies sound override
paths from gp_AuGlobal (+0x108, +0x118, +0x120, +0x228, +0x130), and calls
AuGLEffects::InitializeAudio. This is the same path for game and designer.

AuGL13.dll 0x1800388d0 InitializeAudio opens the default OpenAL device,
creates/makes current a context and stores it at effects +0x990. It can
preload sfx.har into the sound-effect buffers. AudioBuffer at 0x18000c9b0
uses that shared effects object's cache and the configured override path
before the default sound path. AuAtomRenderInfo::~AuAtomRenderInfo at
AuAtom13.dll 0x1800c21f0 deletes its effects object; AuGLEffects destructor
at AuGL13.dll 0x180035ea0 destroys the context and closes the device.

The modern source moved this service to AuApp::InitializeSound and AuSound;
AuDesignerView passes auApp->Sound() into its render info. Borrowing the
application sound service and global gains is the appropriate modern reuse
of that native common-client path. Do not describe a second AuSound or
private global settings object in the legacy widget as recovered behavior,
or claim that the 2016 binary literally used the newer AuSound class.
