2016 offline designer: machinery state and startup announcement
==============================================================
Read-only Ghidra recovery against AuAtom13.dll, 2026-10-05. No build run.
The user checked the original: switching systems on announces startup, but
physical equipment textures remain inactive. This supersedes their initial
report that the textures begin animating.

Switches and initialization
---------------------------
DpConsolePilot::ProcessControlInput 18060e130 and
DpConsoleEngineer::ProcessControlInput 1805fdbf0:
- Power toggles independently of the ship's New state. Pilot case 0x14;
  engineer case 0x0e (0x0d is turn-skew hold, not power).
- Maneuver on/off and off/on/hold controls are blocked while New unless the
  power-plant switch is on. Fuel/charge are not tested here.
- On/off: Off or Invalid -> On; On or Hold -> Off.
- Cycle: Off -> On -> Hold -> Off; stations skip Hold.
- Full/hold requires not-New; Off does nothing and stations cannot enter Hold.
TurnPowerPlantOn 1800dc9a0 requires installed plant units and no repair timer.
SetGravityDriveState 1800d8c20 requires installed maneuver units and no repair
timer. On an actual state change it calls SetNotNew if the ship is New.
DaSpaceShip::SetNotNew 1804622f0 clears New and sends:
  System initialization complete. Welcome aboard.
Sender is the ship's Id()/Name(), channel Intercom, range Close (0), scope
Intercom (9). It is not a Voice message. The pirate suppression branch has no
relevance to offline authoring. Later switch cycles do not repeat the welcome.

The same announcement survives in modern DaSc::SetNotNew. Its text is now
shared through DaSc::SystemInitializationMessage, preserving translation
context. The legacy view constructs AuCommChat and feeds ChatReceived locally;
it does not require a fabricated sector, network delivery or an Intercom input
tab. AuDesignerView renders it using native channel/scope color, font, filters,
intensity, sound and lifetime. The local preview uses its generated spacecraft
registration as sender, matching the name beneath the target HP bar.

Equipment working state
-----------------------
AnimateDeviceObjects 1803c9950 advances 3/4/7-frame counters every 100ms, but
sets effect UV offsets to (-1,-1) for inactive machinery. Base equipment skins
already contain the off appearance; freezing the first lit overlay is wrong.
- PowerPlantWorking 1800d6160: switch on, fuel > 0, applicable system health.
- GravityDriveWorking 1800cc300: On/Hold, capacitor > 0, system allocation.
- SensorsWorking 1800d8430: sensor switch, capacitor > 0, system allocation.
- Shields use ShieldsWorking; FTL needs state On (2) and capacitor charge.
- Weapon-bay effects (51..54) require a matching recent weapon event (within
  two seconds). Transporter pads use IsTransporterRoomActive (43..46) or
  IsTransporterRoomOn (47..50), otherwise the overlay is hidden.
- A separate FTL charging effect tests capacitor plus FTL/commit state.
- Berth (frames 0..3), life support (8..11), surgery (40..42) instead test
  life-support allocation. They do not require capacitor charge. A healthy
  default design has this allocation when life-support units are installed.
- Working maneuver On selects frames 12..15; Hold selects 16..19.
  Plant selects 20..23, sensors 24..26, shields 27..30, FTL 55..58.
AuShipSystemArray::GetPowerConsumption 1801b2800 reads allocated units, not
instantaneous electrical generation. See WALKTHROUGH-AUDIO.txt and
pseudocode/sound-system-state.txt for empty fuel/charge and simulation bypass.

Implementation boundary
------------------------
The render view retains transient New/plant/drive states per loaded design.
Edits and render-mode changes retain them; New/Open reset them. Removing the
last corresponding equipment unit clears that switch. No design bytes change.
Modern DpConsoleHelm/DpConsoleEngineer supply their inherited station controls
(defaults P power, G maneuver, H full/hold); native DiControlInputArray samples
keys, mouse bindings, wheel and joystick in character input mode. The full
station handlers require a world DaVessel, so their switch logic is adapted
locally. Actions apply only while seated at those two consoles.

Hand input reuses DpConsole::EnumControlPanels and AuQuad intersection, with
the same floor transform used for rendering. Projecting the hit onto the
panel's right/up axes supplies lower-left-relative coordinates to the modern
station's SampleControlPanelInput. It handles pixel conversion and button
rectangles; button activation occurs once on a click release, with drags
cancelled. An intervening ship surface blocks the hit, and blank panel areas
consume the click instead of activating a door behind it.
Relevant retained panel rectangles (256x128, measured from bottom):
  Helm:        power (218,90,16,16), maneuver cycle (236,90,16,16).
  Engineering: power (156,13,16,16), maneuver cycle (156,90,16,16).
These also match the 2016 panel samplers at 18060fc50 and 1805fe390.
Modern pc_PowerPlant*/pc_Maneuver* and ec_Power*/ec_StatusLight* resources
update the buttons/indicators at the native coordinates. At most six texture
variants per console type are cached, shared by all its equipment instances.
Other instrument simulation and unrelated console actions are not added here.

Fuel and capacitor charge remain empty, so machinery effects and their sound
loops stay inactive even after switches are turned on. BindEffect suppresses
those overlays and retains the life-support allocation exception. This is an
offline designer, not a fuel simulation or ship manufacturing implementation.
Manual validation is listed in TESTING.txt; source/resource checks and
git diff --check do not establish Windows compilation, GL rendering or
original-client parity.
