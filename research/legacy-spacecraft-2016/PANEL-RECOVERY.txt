Original 2016 Spacecraft Design panel
=====================================

Recovered 2026-10-04 from the original Shores of Hazeron.exe constructor
0x1402c91e0 (AuTabDesign RTTI) using direct x64 assembly. The constructor's
decompilation exceeded the MCP time limit. inspect_panel_layout.py reproduces
the referenced strings and QGridLayout::addWidget call arguments with objdump;
the tables below retain the interpreted layout. Binary identity: sources.json.

Coordinates below are zero-based Qt grid rows and columns. Blank cells matter:
constructor creation order is not the visible palette order.

Outer grid (14 columns)
-----------------------
  row 0: c0 Depart Studio (dp_Exit, conditional), c1 New (dp_New),
         c2 Load (dp_Load), c3 Save (dp_Save),
         c4 Delete Design (dp_Delete, conditional).
  row 1: c0 Render Mode (dp_RenderMode), c1 Gravity (dp_Gravity),
         c2 Check Paths (dp_Check), c3 Burn CD (dp_BurnCD).
  row 2: c0 Move Grid Up (dp_DeckAbove), c1 Grid90, c2 Grid0,
         c4 Erase Current Deck (dp_DelDeck).
  row 3: c0 Move Grid Down (dp_DeckBelow), c1 Grid45, c2 Grid135,
         c4 Move/Copy Rooms and Equipment (dp_Move).
  Rooms group occupies row 0, column 6, spans 4 rows and 8 outer columns.
  Equipment group occupies row 4, column 0, spans all 14 columns.
  row 5: c0 System Modules (UpgradeModule), c2 ArmorIncrease,
         c3 ArmorDecrease; Streamline Hull checkbox spans c5..11;
         minimum Tech Level dropdown spans c12..13.
  row 6: HTML help/status area spans all 14 columns.

Outer placement call addresses: 0x1402d1cfb..0x1402d2071.
This is the compact shape shown in the user's reference. The apparent deck
arrows on the right of Equipment are brush-size controls. Apparent roof icons
in the last equipment row are vehicle placement tools. Actual dp_Roof* assets
exist but are not placed by this spacecraft panel constructor.

Room group (10 columns)
------------------------
dp_ prefix and .png suffix omitted in these rows.
  r0: RoomMode0, Barracks, Bridge, Brig, CrewCabin, EngineRoom,
      LandingBay, Fuel, [spacer], RoomIdUp
  r1: DelRoomCells, Galley, GravityWell, Corridor, Cargo, CaptCabin,
      OpenToBelow, Lounge, [spacer], [Room Number button]
  r2: DelRoom, SensorRoom, ShieldRoom, SickBay, Stateroom,
      TransporterRoom, WeaponBay, [empty], [spacer], RoomIdDown

The mode button changes its icon to RoomMode1 when changing existing room
types. Draw paints/replaces cells; change mode changes an existing whole room's
type and disallows a duplicate type/number on the same deck.
Room Number button applies the displayed number to an existing room and also
disallows a duplicate type/number on the same deck.

Berth0 invokes DesignDetailBerthSingle; Berth2 invokes DesignDetailBerthDouble.

Vehicle tooltips identify F1, F2, Motor Bike, SUV, APC and Space Transport.

Numeric values and tooltips
----------------------------
AuTabDesign::TimerUpdate at 0x1402d33e0 proves Room Number displays the stored
quint8 subtype plus one, hence visible range 1..256 and initial display 1 for
stored subtype 0. Brush Size also displays its raw byte plus one.
See the saved Qt-metadata-labelled IDA pseudocode; the UI setter/getter field
matches constructor button offset 0xb8 (Room Number) and label 0x50 (Brush Size).

Minimum Tech Level constructor 0x1402ca689..0x1402ca77d iterates raw values
31 down to 0, creates displayed numbers raw+1, stores the raw value in item
data, and initially selects the last item. Visible choices 32..1 therefore
map to header minimumTechLevel 31..0. TimerUpdate selects via findData.
This is the bottom-right dropdown; it controls neither deck nor armor.

Grid tooltips:
  Grid0   Lateral Grid Lines / enable grid lines on the beam.
  Grid45  Diagonal Grid Lines / enable to the port quarter.
  Grid90  Longitudinal Grid Lines / enable fore and aft.
  Grid135 Diagonal Grid Lines / enable to the starboard quarter.
The recovered grid bits remain 1,2,4,8 respectively, default 5.

Streamline Hull tooltip says atmospheric maneuvering speed increases and
spacecraft mass rises 10%. Armor Increase/Decrease tooltips describe increasing
or reducing physical defense and mass. The constructor itself does not prove
the permitted armor range; do not infer a range from its two buttons.

inspect_panel_layout.py also extracts offline_spacecraft_help, containing
the old walkthrough, save, load-in-game and
Burn CD instructions. Those instructions describe 2016 capabilities and must
not advertise unsupported actions in the new panel.

Header control behavior
------------------------
Streamline is a Boolean UI choice: AuAtom13.dll SetDesignStreamline(bool)
0x1804618b0 delegates to AuData13.dll 0x180149f90, which changes the byte at
DnSpaceShip+0x14 only when different (getter 0x18014a090). Its shared tiny
store may be labelled AuItem::SetHitPoints by Ghidra; that alias is unrelated
to the control's meaning. A modern multivalue selector does not establish a
multivalue 2016 control.

Armor increase/decrease (AuData13.dll 0x180144420/0x180144320) step by one,
refusing increase at >=10 and decrease at zero. Low-level SetArmor(short)
0x18017e3a0 only narrows/stores at +0x15; displaying an unusual loaded byte
must not silently normalize it. Both controls reject read-only designs and
notify changes; AuAtom wrappers 0x1804615d0/0x1804616c0 and streamline also
check CanDesignBeModified and invalidate cached geometry/path after success.

The working constructor (AuData13.dll 0x180178f70) stores ushort 1 at +0x14:
new streamline=1, armor=0. Loading preserves saved values. Header edits mark
the native session dirty; their 3D effects await the deferred renderer. Raw
control captures are in pseudocode/ship-header-control-evidence.txt.

Room labels in the edit view
-----------------------------
AuAtom13.dll RenderDesign 0x18041a5b0 labels each room on the active deck.
The label loop at 0x180421fc0 takes boundary[0], projects it to screen space,
and formats "%1 %2": SpaceShipDesignRoomName(type) and Number()+1. Number is
the subtype byte, not the persistent record ID. It renders black text at
(x,y), then room-colored text at (x-1,y-1), with flags 0x141 (AlignLeft,
AlignBottom, TextSingleLine). Text stays screen-aligned and fixed-size.
The RGB float table starts at 0x180a0e620, 12 bytes per type, types 0..24;
e.g. Engine Room is #b7b7b7, Hold #ddc358 and Weapon Bay #3258c9.

The focused assembly capture is pseudocode/room-label-assembly.txt; the whole
RenderDesign decompilation timed out. AuData13.dll SpaceShipDesignRoomName
0x180149110 looks up the original spacecraft name in the room-type definitions.
The current view uses its recovered RoomName table and preserves its numeric
fallback for unknown types. Labels use the native UI font at 16 logical pixels;
original user-configured font settings have not been recovered. They draw over
equipment, accept no mouse buttons, follow room-layer visibility, and regenerate
when loading, changing decks or editing boundaries. No 3D renderer is required.

Assets and native scope
------------------------
AuLegacyShipIcon in src/lib/designer/legacy/aulegacyshipicons.h/.cpp supplies
111 exact original PNG payloads, all 103 dp_ icons plus the eight non-dp icons
used by the panel. It accepts base names, .png filenames or :data/ paths and
works without Qt resource initialization or external legacy DLLs.
No recoloring, image editing, scaling or PNG rewriting was performed.

inspect_panel_icons.py statically decodes version-1 Qt resource trees from:
  AuSceneClientRes13.dll registration 0x1030: 103 dp_ icons.
  AuData13.dll registration 0x1140: Troop and six vehicle icons.
  AuGlobal13.dll registration 0x28d0: UpgradeModule.
panel-icons.json records original DLL SHA-256, per-icon SHA-256, dimensions,
byte counts and resource names. Existing modern dp_ resources are under
resources/client/mail/data but omit many of this panel's icons; the helper
preserves the complete original set for both launch paths.

The native panel docks right by default, toggles with F6 and retains a
Selection tab, Fit/Inspect controls and tool description for the 2D workflow.
Deck up/down covers -28..28 with no deck dropdown. Depart Studio/Delete Design
are omitted in this offline session. Unimplemented tools stay disabled with
explanatory tooltips; Draw selects painting and Room Number selects the brush
subtype rather than reassigning an existing room. README.txt lists current
scope; TESTING.txt contains the manual panel checks.
