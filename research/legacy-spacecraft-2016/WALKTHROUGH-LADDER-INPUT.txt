2016 ladder direction and run modifier
=====================================

Recovered through Ghidra MCP from AuAtom13.dll and AuData13.dll. This corrects
the earlier fixed W=up/S=down mapping in the legacy renderer.

AuAtom13.dll DaPerson::Acceleration, 0x18031be50:
- Forward/backward actions supply local (0,+1,0)/(0,-1,0).
- The branch at 0x18031c248 includes IsLadderPose in the conditions selecting
  CurrentHeadTilt + AuPoint::RotateX instead of ground-slope alignment.
- Thus forward contributes sin(headTilt) vertically; backward reverses it.
  Level forward input contributes no vertical force. This is a continuous
  pitch projection, not an up/down toggle at a chosen camera-angle threshold.
- Explicit down contributes Z=-1; explicit up contributes Z=+0.5 and is allowed
  in ladder pose. Forward, lateral and vertical inputs are combined, then
  normalized to the movement force. Existing velocity, friction and speed caps
  still apply; pitch alone is not a complete formula for final climb speed.

AuAtom13.dll DaCreature::FilterFinalMoveVector, 0x1802e9720:
- Poses 0x4a/0x4b zero X and Y, retaining Z. Looking or strafing cannot move
  the attached avatar off the ladder axis.

AuAtom13.dll DaPerson::ProcessControlInput, 0x18033ab90, and
DaPerson::SelectPoseForMeOrMount, 0x18034ce60:
- Input processing sets ACT_Run (0x4000) for forward input with the run modifier.
- Pose selection tests the movement mask 0x3000f. For an existing ladder pose,
  it returns LadderClimb (0x4b) immediately, before checking ACT_Run or stamina.
  Without movement it returns Ladder (0x4a).

AuData13.dll DpBody::MovementSpeed(POSE), 0x1800d0050:
- LadderClimb (0x4b) uses 0.75 * (DNA speed + 1). The default human's speed
  nibble is 4, so this is a 3.75ft/sec body-speed parameter, not a guarantee
  of final vertical velocity. Ladder (0x4a) has zero movement speed.
- StandRun uses a different pose/factor; there is no faster ladder pose or
  run-dependent factor in this path. Shift therefore does not accelerate
  climbing in the recovered 2016 implementation.

Implementation
--------------
The modern DaPerson::Acceleration, SelectPoseForMeOrMount and DpBody movement
speed retain these rules. Remove only the legacy renderer's forward/backward
to up/down conversion; pass controls (including rebound and continuous forward)
to the existing controller. Keep native XY filtering and local ladder collision,
attachment and release handling. No new movement or speed formula is needed.

Validation (manual client build required; none initiated by the assistant)
------------------------------------------------------------------------
Attach with E at a hatch midway along a clear ladder. Hold W and sweep pitch
up/level/down without releasing it; check ascent/no new vertical force/descent.
Repeat with S and continuous forward, multiple hatch orientations and rebound
controls. Compare the same pitch with/without Shift: speed should not increase.
Check C/Z at both pitch extremes, combined inputs, fixed XY, automatic/manual
hatch blocking, stacked ladders, E/Space release and focus-loss input cleanup.
This change was source-reviewed against the decompilation, not runtime-tested.
