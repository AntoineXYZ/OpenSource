Native .ship reader validation
=============================

These sources are outside the game targets. No build or native test has been
performed by the assistant. The user must build the harness manually.

On WSL/Linux with Qt 5 development headers/libraries and pkg-config installed,
run this yourself from the repository root:

  c++ -std=c++11 -fPIC -no-pie \
    -Isrc/lib/data/designs \
    research/legacy-spacecraft-2016/tests/native_ship_reader.cpp \
    src/lib/data/designs/aulegacyship.cpp \
    $(pkg-config --cflags --libs Qt5Core Qt5Gui) \
    -o /tmp/native_ship_reader

Then run:

  /tmp/native_ship_reader --self-test

The synthetic streams use Qt's actual Qt_4_0 QDataStream writer as an independent
encoder. Tests cover versions 0/1/2, every truncation of three complete fixtures,
exact EOF, unsupported versions, odd and oversized UTF-16 lengths, null/empty
strings and lone surrogates, raw fields and normalization scope, signed deck/XY
extremes, count and file-size limits, atomic failed reads, ellipse facet counts,
clockwise geometry, stored controls, and degenerate ellipse handling. The combined
record-budget test includes enough bytes to pass the preceding byte-count check.

Compare all three original samples against the Python reader:

  python3 research/legacy-spacecraft-2016/tests/compare_native_reader.py \
    /tmp/native_ship_reader \
    "/mnt/c/Users/Celarious/Desktop/Shores of Hazeron/Antiflux Harvester MK2.ship" \
    "/mnt/c/Users/Celarious/Desktop/Shores of Hazeron/B8_Galatine_A1.ship" \
    "/mnt/c/Users/Celarious/Desktop/Shores of Hazeron/tl20StarDriver.ship"

The comparison runs the already-built harness; it never builds anything. It checks
every original record field, normalized value, decoded coordinate and stream
offset. Unknown-offset JSON labels are retained to match the original inspector,
even where subsequent evidence supplied semantic names in the native model.

To inspect the native dump directly:

  /tmp/native_ship_reader "/path/to/example.ship"

No command above modifies a .ship file. The native reader is read-only. Passing
these checks validates recovered stream/geometry handling, not editing behavior,
room-purpose names, original visual appearance, or .SoH conversion.
