Original 2016 spacecraft surfaces: implementation and evidence
==============================================================

The offline legacy designer now has a textured orbit view behind the original
Render Mode button. It shares the in-memory authoring design with the floor
plan; it does not convert designs to the modern world/scene model. New/Open,
cell edits and armor changes invalidate the mesh. Returning to either view
preserves that view's camera. The existing F action fits the active view.

Source map
----------
src/lib/designer/legacy/aulegacyshipmesh.h/.cpp:
  CPU triangle batches, original spacecraft material IDs, deck classification,
  finite bounds and recovery warnings. Positions remain in authoring feet,
  with x/y on the plan and z up. No OpenGL context is needed to generate them.

src/lib/designer/legacy/aulegacyshiprender.h/.cpp:
  Qt OpenGL orbit/pan/zoom, original atlas tiles, depth testing, opaque frames
  plus depth-sorted translucent window triangles, and GPU context lifecycle.
  The selected-deck cutaway clips at deck*8+4 feet. This is an added inspection
  aid for the requested orbit camera, not an asserted original 2016 control.

The normal client already initializes AuTexture. The standalone path now
initializes the same resource bundle and sets the GL format before QApplication.
Textures are loaded from :/data/txSpacecraft0Lit.png, never from the repository
or a legacy installation. Atlas regions are the original SHIP_TEXTURE table
retained in AuBodyRenderWidget::ShipTexture and verified against the binary.

Recovered surface pipeline
--------------------------
DaSpaceShip::CreateModels, AuAtom13.dll 1803df500, calls RenderExterior for the
exterior model, then RenderInterior and an interior-facing RenderExterior pass.
The native mesh follows this separation with outward/inward triangle winding.

RenderExterior 180426360 and RenderInterior 18042f410 process decks at 8-foot
spacing with a persistent 516x516 unsigned-short floor buffer. The native
buffer ports FillFloor (AuData13.dll 1801713a0), including directed scanline
fills and the 16-bit deck/tag state. Room cells are sampled in four triangles
per 5.656854249-foot full square at quarter-grid offsets (3,2),(2,3),(1,2),(2,1).
This covers the original square, triangular, diamond and parallelogram paint
cells, concave outlines and negative coordinates without a polygon-fan fill.

Ordinary tag is ((type&31)<<8)|subtype. At deck transition, stale 0x8000 samples
are removed, 0x2000 is cleared and remaining coverage gains 0x8000. Current
coverage over previous 0xc000 gains 0x4000. Open-below 11/15 over prior ordinary
coverage preserves the previous low tag and sets 0x6000; over fuel 9 it keeps
the current tag and sets 0x4000; over no prior coverage it keeps the current
tag. Consequently an open-below room does not simply lose every bottom face.
Current ownership is tracked separately for internal room partitions.

The original floor/ceiling/bottom/top predicates and material choices are
ported. Neighboring decks suppress hidden hull planes; open-below coverage
suppresses the connecting floor/ceiling as appropriate. Bridge and Lounge
use glazed exterior horizontal surfaces; Captain's Cabin and Weapon Bay
also do so below their recovered armor thresholds. Fuel has no internal
partition pass, but retains the original horizontal and reverse hull faces.

DnRoom::WallProfile (AuData13.dll 180174d00) supplies all spacecraft palette
room profiles and armor 0..10 changes. Profiles run from z 0 to 8, with the
original offsets, intermediate heights and opaque/window strip choices.
Boundary loops exclude internal hull walls, merge collinear matching spans,
join corners and close differing room-profile junctions. Interior partitions
use Finished, Cargo or Equipment materials by original room-type switches;
short spans use the corresponding fill tile. See RENDERING-MATERIAL-EVIDENCE.txt
for exact IDs, thresholds, hatch/door dimensions and supporting addresses.

Square-center hatches use a 4-by-4-foot aperture; corner and edge hatches use
the recovered diamond with radius 2.8284271245 feet. Convex clipping replaces
the original numerous neighbor-specific triangle branches. The recovered
footprints and surface predicates are preserved, but identical triangulation
and UV interpolation at every transition have not been established.

Small doors use five-foot spans; large interior doors/openings occupy the
whole partition span. Large hull doors/openings retain one foot at each end.
Hull doors use their recovered profile and seven-foot door face. Hatches and
doors use their original closed atlas tiles for this static preview. The
original runtime selected animation frames separately; that is not ported.

Streamline Hull correction
--------------------------
The previous deferred-recovery note inferred streamline-dependent geometry.
Further recovery disproved that inference. DesignStreamline 1803e5a80 is read
by HullStress, MaxAtmosphereSpeed, MaxAtmosphereThrottle and a UI accessor.
A complete cached-field reference search found only its analysis writer and
getter. The recovered surface functions depend on armor, not streamline.
The checkbox therefore retains its physics/design meaning without inventing
a visual deformation. See pseudocode/streamline-physics-consumers.txt.

Validation and remaining boundary
---------------------------------
No compiler, build, native harness or client was run by the assistant. The
user must build manually. Source checks and independent Python raster/asset
checks passed; TESTING.txt contains the native CPU harness and manual visual
comparisons. These do not prove original-client visual parity.

The original Render Mode icon, palette position, tooltip and boolean toggle
are preserved. The orbit camera, clipping and lighting are new viewer code;
they do not reproduce avatar navigation or a world environment. Exact original
shading/effect textures, furnished equipment, animated doors/hatches, turrets,
railings, ladders, stairs and building roof types 22..24 remain outside the implemented surface baseline.
Unsupported room/detail cases are reported in the inspector instead of being
represented by invented equipment boxes. Scene/world rendering is deferred.

All original executables, DLLs and ship samples remain read-only.
