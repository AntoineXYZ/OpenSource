2016 equipment reconciliation after room painting
Captured and translated 2026-10-04. No compiler or game build was run.

Entry points
------------
AuData13.dll SpaceShipDesignVerifyDetails 0x18014b3f0 processes details in
existing list order. SpaceShipDesignTestDetail 0x18014a730 calls
DnDetail::IsValid 0x18015c9d0 and writes corrected type and room ID only on
success. Earlier deletions and corrections are visible to later records.
The native port is src/lib/data/designs/aulegacyshipdetails.cpp. It computes
against a temporary detail array and commits only when every dependency can
be evaluated. Invalid placement removes a detail exactly as in the old pass;
unavailable model information rejects the edit without partially deleting
equipment. Rooms are supplied through RoomBoundary, including working edits.
Empty source room records remain available to the file inspector but are
excluded from reconciliation's room array, matching the original loader.
This also excludes them from room-ID/subtype lookups for weapon emitters;
the pivot extent calculation independently ignores empty boundaries.

Original detail-type definitions
-------------------------------
The fresh 2016 distribution's GD starts 18 3a, followed by a big-endian u16
detail count. Its 143 records end at offset 52431 (0xcccf). DnDetailType::Rx
0x180165600 reads u8 type; four Qt QStrings; u8 bridge flag; u16 crew;
i16 placement; u8 minimum technology; u16 mass. inspect_detail_types.py
reproduces extraction without modifying GD; detail-types.json contains the
original GD hash and the fields needed to audit the native constant table.
The program's GD loader is 0x18013dc40. This port does not need GD at runtime.

The placement field means:
  >=0  requested room purpose, with bridge exceptions from each type record.
  -1   living quarters (room types 1,4,7,19), interior, with berth foot test.
  -2   exterior wall, exactly one room, not a boundary vertex.
  -3   interior wall, exactly two rooms, not a boundary vertex.
  -4   interior floor, exactly one room here and one below.
  -5   exterior floor, exactly one room here or below.
  -6   entire design's XYZ extents, including 8 feet above highest room.
  -7   emitter location in a room, avoiding duplicate type at the same XY.
  -8   flag/light placement; no rooms; spacecraft ultimately rejects it.
  -9   stairs, handled by a separate seven-point footprint test.
  -10  troop station, room interior; outdoor allowance is building-only.

General room-space checks
-------------------------
Details require abs(deck)<=42 and signed half-grid XY within [-120,120].
The original table must contain the detail type. All matching room boundaries
are visited in order, including roofs. Non-bridge-allowed details cannot be
on/in bridge rooms. Fuel rooms reject ordinary wall/floor details, with the
original special-case exception for dtype98 in the exterior-wall branch.
Floor details also examine deck-1 and reject a wall line or fuel room below.
An interior hatch cannot be above two rooms. Association is the last matched
same-deck room; an exterior floor detail outside a room gets the room below.
Turrets retype to 0x21 inside the current room or 0x16 above a room; side
turrets retype to 0x15 or 0x22..0x28 from the closest wall's outward normal.

Named rooms use the recorded required room purpose, with bridge permission
as a fallback. Game tables additionally allow room purpose10. Boundary
placement is allowed for dtype10,14,16,18,23,99 but not other named-room
equipment. One-per-room types are 1,4,6,7,11,12,13,15,17,19. Type99 weapon
emitters are limited across all decks by their rooms' subtype/Room Number.
Duplicate checks compare persistent detail IDs, matching the old code.

Spacing, footprints, and original edge cases
--------------------------------------------
DnDetailType::MinPlacementSpacing 0x180163890 supplies zero, 1,
2.7450937911666666, 5, 7.071, or a rotated vehicle half-extent per axis.
Spacing rejection uses strict abs(deltaX)<sumX AND abs(deltaY)<sumY, only
against other details on the same deck whose current stored room ID matches.
The current detail checks spacing only when BOTH its dimensions are nonzero;
the other detail participates when EITHER of its dimensions is nonzero.
Flag/flag and light/light pairs are ignored by this spacing pass.

Vehicle fit rotates the swapped model half-extents using float Rotation(type)
promoted to double. Vehicle spacing uses exact double pi/4 multiples instead.
Both first convert model half-extents to float. Only dtype0x39..0x40 has a
nonzero VehicleCID (0x180047690); old fighter types0x29..0x30 do not enter the
vehicle-fit branch and their spacing is zero. Do not infer extra validation
from their names.
The vehicle half-extents are baked from the original resource DLL, with
provenance in vehicle-bounds.json. All15 original vehicle commodities are
covered. Four absent original assets (54,70,71,103), and commodity0's empty
model, reproduce the original null-geometry zero-extent fallback. Unexpected
commodity IDs without recovered asset evidence reject the transaction rather
than guessing a footprint or treating unknown equipment as valid.
The 45-degree game-table fit uses the exact double pi/4 constant, not the
float angle returned by Rotation(0x4b); instructions0x18015d8c9 and
0x18015e415 confirm its separate XMM7 argument.

Stair checks use double dimensions and seven rotated points. The first point
collects acceptable rooms on the stair's SAME deck, excluding fuel and roofs;
each later point must be in/on one of those candidate rooms. The original
does not narrow the candidate set between points, does not set a new room ID
in this branch, and does not test an upper deck here. StairBoundary
0x180161ae0 is distinct: its collision-outline dimensions are floats.

Confirmed original spacing bug: when testing another detail that is stairs,
IsValid tests the STAIR'S OWN origin against StairBoundary, not the current
detail position. Assembly 0x18015e703..0x18015e727 confirms the argument comes
from [RBX]+0x10, where RBX points to the other detail. The port preserves this.

Geometry primitives
-------------------
AuMath13.dll PointInBoundary 0x18000ce40 survives in modern aupoint.h and was
cross-checked against the original. It rejects strict XY bounding-box edges,
rotates an extent-sized ray by one degree, uses PerpConn with tolerance1e-5,
and rotates again on ambiguous vertex intersections, up to360 vertex retries.
The native equipment helper preserves this rather than Qt's polygon test.
PointOnBoundary uses nearest-segment distance<=1e-5; DoesContain uses
component-wise fuzzy equality<=1e-5. The latter matters when disallowing
wall endpoints. ArcTangent_2D snaps near-zero axis components before atan2.

Validation boundary
-------------------
The 143 compiled-in placement/bridge records were compared field-for-field
with a fresh read of the original GD; all matched. The independent Python
integer-grid placement audit in tests/check_detail_placements.py was run on
all three original ships: 2040+2235+4053=8328 details, zero violations of the
tested room-purpose, bridge, wall/floor and deck-count rules. That audit does
not execute the native code or test spacing, rotated footprints or mutation.
All15 compiled-in vehicle half-extents and their float32 narrowing were also
compared exactly with the independently extracted vehicle-bounds.json table.
An independent source review checked reconciliation/list order, placement
branches, spacing, stair semantics and C++/Qt plausibility without compiling;
no concrete translation issue was found in that review.

tests/native_detail_reconciliation.cpp is a manual native harness covering
room reassignment/removal, bridge permissions, ordered duplicate removal,
side-turret direction and endpoint rejection, shared-wall doors, two-deck
hatches, top/bottom turret retyping, cross-deck weapon emitter limits, and
atomic rejection of an unavailable vehicle dependency. It has not been built
or executed by the assistant. The new equipment pass still needs direct
before/after 2016-client fixture comparison; static recovery is not a claim
that those end-to-end comparisons have occurred.
