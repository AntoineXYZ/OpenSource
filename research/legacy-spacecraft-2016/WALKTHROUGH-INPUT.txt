2016 designer walkthrough input refinement
==========================================

Source evidence
---------------
Shores of Hazeron.exe 0x1400da300 initializes the original view controls:
  Input Mode Toggle, Avatar vs Hand: ID 8, Return (Qt 0x1000004),
    mouse type 7 (right button), no modifiers.
  Hand Input Mode, Temporarily: ID 7, Control (Qt 0x1000021),
    ControlModifier 0x4000000, continuous while held.
  Open Door / Close Door remain Ctrl+P / Ctrl+C.
The temporary-hand tooltip explicitly covers grabbing items, opening doors,
using in-game consoles and operating interface windows/dialogs.

The surviving modern AuDesignerView::ProcessControls, SetCursor, GrabMouse,
ReleaseMouse and AssessInputMode retain the associated mechanism: avatar
input hides/grabs the pointer and measures movement while recentering it;
hand/UI mode releases it, and focus loss releases the grab. The original
hand artwork remains in AuClientRes. Both Legacy launch paths initialize the
normal client application and frame, including shared resources, game globals,
settings dialogs and the joystick service.

Local implementation
--------------------
AuLegacyShipRender extends AuDesignerView, using its scene-interface GL setup,
RenderViewButtons, hit testing, tooltip handling, cursor selection and window
action dispatch. The new VB_LegacySpacecraftDesign is appended to the button
enum so existing saved button IDs retain their values. It invokes the frame's
ToggleDesignPartsUi. Floor-plan editing is a child canvas beside the same
sidebar; walkthrough uses the full scene area. Button style, size, visibility,
transparency and fade behavior come from the native implementation.

The controller reads Avatar actions from DaPerson::EnumControlInputs and scene
mode actions from AuDesignerView::EnumControlInputs. It uses DiControlInputArray
for keyboard/modifier, mouse, wheel and joystick sampling. ControlsChanged
reloads bindings from the normal Settings dialog and clears held movement.
Supported actions cover movement, look, running, continuous forward movement,
jumping/braking, ladder entry/exit and opening doors. Window bindings use the
normal frame dispatcher. Binding dialogs suppress window shortcut dispatch.

The renderer enters avatar input when the walkthrough is focused. It polls
the real pointer and recentres it each update, avoiding queued warp events
as movement input. Configured scene bindings toggle hand mode or temporarily
release capture (defaults Return/right-click and Ctrl). The application event
filter observes temporary-hand key releases over tool windows without consuming
their events. A platform modifier query reconciles modifier keys after switching
applications. Actual mouse-grab ownership is checked when grabbing is enabled.

Hand mode uses native cursor selection and left-click panel interaction.
Movement keys apply in avatar mode; Ctrl+P/C still operates nearby doors while
the hand is temporarily released. Mouse capture releases for dialogs, focus
loss, application deactivation, hidden render views and destruction. Original
Escape-to-exit behavior of this reimplementation is retained. The legacy
Ctrl+P/C and Home fallbacks yield to configured supported control bindings.

The yellow crosshair uses the existing modern HudItems.png artwork and the
layout in AuGLEffects::RenderCrosshair, adapted to the local QPainter overlay.
It is drawn independently of mesh presence, including an empty new design.
No crosshair artwork is extracted or generated. Native ship target/health
behavior is documented separately in WALKTHROUGH-RECOVERY.txt.

Limits and validation
---------------------
The legacy geometry still requires its own movement/collision adapter; it does
not instantiate the modern world atom/pose simulation. Input definitions,
sampling, scene interface, settings and audio are shared with the game.
FOV uses g_Au.FieldOfViewY with AuGLEffects::WindowFieldOfViewY for both projection
and door-click rays. Mouse sensitivity uses the native degrees-per-view-width
setting instead of a fixed degrees-per-pixel constant. Platforms that reject pointer warping, notably
Qt 5.12 Wayland, cannot provide unlimited relative look through this QWidget
API. Sampling the actual post-warp position prevents stationary view spin
on those platforms; native relative-pointer integration remains separate.

No build or compiler was invoked. Source review covered cursor ownership,
focus/hide/destruction, modifier loss across application switches, modal
dialogs, hand-click routing and separation from authored .ship data.

Manual checks after the user's build:
  - Enter from the chooser and with -legacy-spacecraft. In both views, use
    the sidebar to hide/show the tools and open Settings without a keyboard.
  - Change button size/style/transparency, FOV and sensitivity; confirm live
    updates and correctly aligned door clicks after FOV changes.
  - Rebind movement, run, look inversion, avatar/hand toggle, temporary hand
    and the Design Parts window shortcut; confirm the new bindings apply.
  - Hold a window shortcut while releasing movement keys; it should toggle
    once. Configure shortcuts in the binding dialog without activating them.
  - Switch render/floor plan, float tools, change focus, open a modal dialog,
    alt-tab and toggle full screen; check capture and movement recovery.
