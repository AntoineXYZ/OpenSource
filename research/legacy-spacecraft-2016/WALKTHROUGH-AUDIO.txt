2016 designer walkthrough audio
==============================
Recovered 2026-10-04 with read-only Ghidra MCP queries against the original
AuAtom13.dll. This work concerns walkthrough audio, not path validation.

Original ownership and playback
-------------------------------
DaSpaceShip::RenderAudioSources (0x18040f290) and
DaCreature::RenderAudioSources (0x1802ec860) receive the scene's shared
AuGLEffects object, obtain buffers from that service, and configure their
own OpenAL sources. Source positions pass through the scene model/camera
matrix. The designer did not use separate preview audio resources.

The reimplementation borrows the game's initialized AuSound through
SoundSession::SetAudio. It uses AuSound::AudioBuffer, existing sfx.har
resources, and global sound settings. It owns only its source handles.
It never opens a device, creates/destroys a context, parses WAV files,
changes the shared listener, or destroys shared buffers.

SetAudio requires the initialized engine context to be current. The renderer
refreshes the provider from AuApp::Sound each tick. Clearing the provider
after engine shutdown is safe: context identity is checked before accessing
the backend or sending source IDs to OpenAL. It also protects against IDs
from a replaced context.
Source positions are projected into camera coordinates and marked relative.
Stop removes this session's sources on hide/deactivation. SetDesign rebuilds
the ambient emitter locations and clears pending door events.

Doors and hatches
-----------------
AnimateDeviceObjects (0x1803c9950) queues a sound only on the first
100 ms animation tick, when an endpoint frame changes to the half-open
frame. Reversing while already halfway does not queue a new sound.

Four shared per-ship channels exist:
  Detail types          Channel       Close/open SOUND_EFFECT values
  3, 53, 54             Cargo         6 / 7
  50                    Exterior      8 / 9
  8, 51, 52, 77..97     Hatch         10 / 11
  5, 49                 Interior      12 / 13

The newest event in each family replaces the previous queued event, and a
new event interrupts that channel's previous clip. Stacked door panels do
not produce a chorus of simultaneous copies. Unrelated families can sound
together.

Inside the ship, emitters are the door segment midpoint plus four feet,
or the hatch opening point at floor height. The original outside rendering
places the effect at the ship center. Original gains, before overall gain:
  Cargo/exterior: 2 aboard, 10 outside.
  Hatch: 1 aboard, 2 outside.
  Interior: 2.
The hatch outside factor and plant gain were checked against the assembly
because the decompiler omits several floating-point call arguments.

The existing sound table is reused verbatim. In particular its cargo file
names are reversed: CargoClose selects DoorCargoOpen.wav; CargoOpen selects
DoorCargoClose.wav. No speculative filename correction was made.

Footsteps
---------
DaAtom::CreateEnvironmentQuery (0x1802049a0) assigns ground enum 3 on a
ship deck and 2 on the designer plane. Creature rendering selects
SOUND_FootstepsForest + ground - 1, hence Metal and HardFloor respectively.

Footsteps are a looping recorded effect while a grounded walking pose is
active, not an artificial series of timer-triggered clicks. The walking
pose can remain active while pushing against a wall. Airborne/free flight
does not produce footsteps. The default human has one walking pair.

Original pitch:
  1.5 * poseSpeed / (1 + 4 / (DNA.Speed + 1))
Default 2016 human DNA Speed = 4; poseSpeed is 1 walking, 2 running,
and .5 crouch/ladder. This yields .833333, 1.666667, and .416667.
The run sound multiplier differs from the 2.5 movement speed multiplier.
The 2016 creature playback explicitly uses reference distance 1 foot and
rolloff 1, with the source at the feet.

Original loudness scales by sqrt(body volume) / 2. The current fixed human
preview uses gain 1 rather than instantiating the original procedural body.
Its fixed eye height also affects attenuation, as it does other perspective
and collision behavior. These are documented approximations.

System ambience and initial state
--------------------------------
The ship renderer also supports:
  Power plant: SOUND_PowerPlant / SpaceShipRumble.wav.
  Sensor: SOUND_Telemetry / Telemetry.wav.
  Maneuver drive inside/outside: SOUND_GravityDriveInt/Ext /
                                RocketBlastInt.wav, RocketBlastExt.wav.
Inside audio follows the nearest relevant machine; outside audio uses
the ship center. There is one source per system family, not one loop per
equipment object. Plant gain is .5 aboard, 1 outside, with an aboard
minimum gain of .0125. Drive gain depends on normal/hold power and thrust;
the local stationary preview supports the zero-thrust normal/hold values.

The source evidence does NOT enable these loops merely because equipment
exists:
  PowerPlantWorking 0x1800d6160: on flag + positive fuel, with health check.
  SensorsWorking 0x1800d8430: sensors flag + capacitor + sensor power.
  GravityDriveWorking 0x1800cc300: On/Hold + capacitor + system power.
None of these predicates has a designer override.

The constructor 0x1803c1ec0 zeros the power/sensor flags, drive state, fuel
and capacitor. Create 0x1803dcb00 only initializes the FTL state.
DesignLoad, DesignLoadWorking, and the captured offline startup do not
turn those systems on. Tick returns around world simulation in the designer;
Tock returns before system simulation. TickOnClient 0x18046d570 reconciles
modules and calls GatherSystemsData; the gather functions only populate
systems data and timestamps. Refresh copies state; RxUpdate deserializes it.

Consequently the added optional powerPlantWorking, sensorsWorking and
driveState inputs default to OFF. The avatar gravity checkbox must not
enable drive noise. Original system control operation/power simulation is
not implemented by this audio pass. The dormant ambient paths are ready
for those controls; they must not be represented as always-on ambience.

Remaining local-preview differences
-----------------------------------
The outside ship-center emitter currently uses the authored room bounds'
midpoint rather than the original ship mass/center calculation. Ambient
machine centers use authored detail positions at deck height plus four.
Full world/environment audio attenuation, procedural body volume and
multiple limbs, driven vehicles, weapon firing, and console/system control
simulation are outside this local walkthrough pass.
